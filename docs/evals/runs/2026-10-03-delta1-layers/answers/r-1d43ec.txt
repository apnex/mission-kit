### layer-charters.H5
A rule must declare `trace` in frontmatter: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md, Member shape). The schema enforces this. schemas/catalog-entry/v1alpha1/catalog-entry.schema.json has a conditional: if `category` is `rule` and `id` matches `^RU[1-9][0-9]*$`, then `trace` is required. A rule may optionally declare `enforced-by`, which names the tool that checks it, with the pattern `^tools/`. `tools/check-enforcers.sh` checks that the tool exists. "a rule with no tool yet is still a rule, and is checked by reading the trace" (rules/README.md). The schema's `trace` description agrees: "Naming a tool that checks it is enforced-by's job, and is optional." A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md).

### layer-charters.H6
methods/README.md states the order ("the one statement of it"), and rules/README.md and practices/README.md cite it. Ask in order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? If yes, it is an axiom (`axioms/`).
2. Does following it produce a result of its own (a verdict, an artifact, a record)? If yes, it is a procedure or method (`methods/`).
3. Does it govern how an artifact is written, meaning its form, whatever the work was? If yes, it is style (`style/`).
4. Does it leave a trace in the record of the work that a check could test? If yes, it is a rule (`rules/`).
5. Otherwise, it is a practice (`practices/`).

### layer-charters.H7
The moment is *handing over*: passing work in progress to another agent or a later session. methods/README.md: "*Handing over* ... has no procedure at all", and "a lone agent hands over to its own next session". rules/README.md lists handing over among the moments that "hold no rule today". Handing over is the only moment that all three sets name as empty.

### OBSERVATIONS
- practices/README.md "Gaps tested" names only *verifying*, *deciding what to keep* and *handing over* as holding no practice. By its own table, though, only *entering* has a practice (PC1), so *committing to a design* and *treating the record* also hold none and are not listed. rules/README.md, by contrast, lists all four of its empty moments.
- rules/README.md says its members "came from `methodology/` and `skills/` in Delta-1", and practices/README.md says "`PC1` came from `methodology/`". The directory is `methods/`, so either the old name is used without explanation or this is a stale name.
- In methods/README.md, the "Rules hold what procedures record" paragraph is followed by `---` with no blank line between them (around line 106-107). In markdown, that turns the preceding line into a setext heading rather than a horizontal rule. This is a formatting defect.
- methods/README.md says "procedures sit at four of the six" moments, and its table lists four. That is consistent. The prose then calls *committing to a design* "thin", which is right, since it holds only M7.
- H2's placement depends on whether a re-read leaves any record. The corpus does not settle which side of the rule/practice line a "done" checklist step falls on.
