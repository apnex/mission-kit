### layer-charters.H1
NOT SETTLED. Of the corpus's layers, `methodology/` (README.md table: "How work is conducted") and `style/` ("How artifacts are written") are the only plausible homes, and M0's discriminator does not separate them cleanly: "what a reviewer would inspect to tell whether the rule was honoured. If they would read the output, it is style. If they would have to know how you arrived at it, it is methodology" (methodology/README.md). A committed credential is visible in the output (the repository), but S0 scopes style to "Doc, commit, and naming conventions" judged as text (style/README.md), which does not obviously fit a secret-handling rule. It is not an axiom, because A0 defines axioms as limits a system is built toward, not tactical rules ("The situated move in axiom clothing", axioms/README.md). The nearest existing coverage is the remediation skill K1 ("A credential has been committed. Rotate first, then scrub.", skills/K1-history-content-scrub.md), which deals with the aftermath, not prevention. GUESS: methodology, as a rule of conduct at commit time, ideally backed by a checker per the README's "Checkable" property.

### layer-charters.H2
By object it belongs in `methodology/`, since it governs the process followed, not the artifact (methodology/README.md, "What belongs here" table), and it falls in the "Verifying" moment. But it probably fails M0's admission tests. Re-reading leaves no trace, which is the fault "The unenforceable procedure ... If nothing distinguishes a run that followed it, it is advice". Also, "A procedure earns one when following it and not following it produce measurably different work, and the difference has actually been observed". R0 adds that "Re-reading one's own work is the weakest check available" (roles/README.md). This corpus has no `practices/` layer for traceless guidance. So the answer the text supports is: methodology if anywhere, and probably not admitted as it stands. GUESS: the root admission rule "Every entry derives from a real finding" (README.md) would also require evidence that it has prevented a defect.

### layer-charters.H3
`methodology/`. It governs conduct, specifically "the evidence you demand before you proceed" (methodology/README.md, Purpose), in the "Verifying" moment. An entry already covers it: M1 "Triangulated review - minimum 4 independent inputs" (methodology/M1-triangulated-review.md). M1 says to "require at least four genuinely independent inputs before reaching a verdict". Its trigger is "You are reviewing a patch or design that ships to production or upstream". So the guidance should strengthen or cite M1 rather than add a neighbour ("Prefer strengthening an existing entry to adding a neighbour", methodology/README.md).

### layer-charters.H4
`style/`, because the rule governs the artifact and a reviewer checks it by reading the output ("If they would read the output, it is style", methodology/README.md; S0 "Rules about the artifact itself, judged by reading the output"). No existing S1-S14 entry covers heading case (INDEX.md, Style section). Admission requires that "its absence has produced a real defect in a real artifact"; "Aesthetic preference does not qualify" (style/README.md). Sentence case is predicate-checkable, so S0 says to "write the tool" and declare `enforced-by` naming exactly one tool, verified by `tools/check-enforcers.sh`. GUESS: without a recorded defect it would likely be refused as aesthetic preference.

### layer-charters.H5
NOT SETTLED. This corpus has no `rules/` or `practices/` directory. Neither appears in the README.md layer table or in INDEX.md, and the frontmatter schema's `category` enum has neither (schemas/catalog-entry/v1alpha1/catalog-entry.schema.json). For all entries the schema requires `id`, `category`, `title`, `status`, `hydrate-when`. `enforced-by` is optional and is described as "The tool that holds this rule". S0 uses it for enforced style rules. GUESS: if such layers existed, a rule would have to declare something checkable (for example a check/trace) and could optionally declare `enforced-by`, while a practice would not. Nothing in this corpus says so.

### layer-charters.H6
The corpus gives no explicitly ordered question list, and it does not define "rule" or "practice" as categories (NOT SETTLED for those two). The text supports this sequence. First, is it always in force or declinable? An axiom is "a standing commitment"; S/M/P/K entries are "situated moves" you reach for when a task touches them (axioms/README.md). Second, for a situated move, what does it act on? The M0 table answers this: process -> methodology, artifact -> style, solution shape -> patterns, executable capability -> skills, "not declinable" -> axioms (methodology/README.md). Third, the tiebreak: "what a reviewer would inspect ... If they would read the output, it is style. If they would have to know how you arrived at it, it is methodology". GUESS: rule vs practice would be decided by whether a check could detect compliance, by analogy with M0's "unenforceable procedure" fault.

### layer-charters.H7
"Handing over" is the moment: "passing work in progress to another agent or a later session - has no procedure at all" (methodology/README.md, Territory). The charter records it as a gap "recorded rather than filled", noting it applies even to a lone agent, which "hands over to its own next session". The charter says "no procedure". Saying that no rule or practice governs it either is my inference: this corpus has no rule or practice layers. The other thin moment, "Committing to a design" (only M7, which applies to extensive design), is thin rather than empty.

### OBSERVATIONS
- The questions assume `rules/` and `practices/` layers. This corpus has neither: no directories, no README.md table rows, no INDEX.md sections, no schema `category` values. H5 and H6 therefore cannot be settled from it, and H1, H2 and H7 only partly.
- README.md line 67 calls INDEX.md "the flat ledger across every category", but INDEX.md is grouped by layer.
- The catalog-entry schema `id` pattern `^(AR|MREQ|SC|A|S|M|R|K|W|D|P|C|E)-?[0-9]+$` has no `T` prefix, although `trait` is a valid `category` and T0-T5 exist (measured by reading the schema; I did not run the validator). Its `description` also lists fewer categories than the enum holds.
- The M0 output-vs-process discriminator classifies "never commit credentials" ambiguously: the evidence is in the output, but the rule is about conduct.
