No. S0: "Style is gated on changed files rather than on the whole corpus. The corpus carries debt that predates the checkers, so gating the diff blocks new debt and converts the rest opportunistically."
`tools/check-all.sh` (lines 99-120) runs the per-rule checkers only on changed `.md` files by default: committed against the base, plus staged, unstaged and untracked. With no changed markdown it prints PASS without running any checker.

### s0.Q6
No, it is a rule, and it already exists as RU3 (rules/RU3-anti-amnesia-deferral.md), whose `trace` reads "every deferred, parked or cut item's record carries a revival trigger".
M0 settles this exact case: "The style question is about the object, not checkability: *every deferral records its revival trigger* is visible in text and is still a rule, because it governs what the work records."

### s0.Q7
S0's Faults section lists the population faults:
- The unfalsifiable convention: phrased as a quality ("be clear", "be concise") with no predicate, cited only when someone already disagrees.
- The orphaned rule: nobody enforces it and nobody reviews it, which teaches readers the layer is decorative.
- The forked enforcer: two tools hold one rule and disagree at the edges.
- The corpus-wide sweep: all legacy debt converted in one commit, giving an unreviewable diff that can hide a real change.
S0's earning criteria add these signs: entries that exist for aesthetic preference, or rules that only hold inside one document.
check-enforcers.sh adds two more: a rule naming a tool that does not exist (a "broken promise"), and a per-rule tool no rule claims ("orphaned").
M0 and RU0 add misfiling: style rules dressed as procedures or rules, filed where writers do not look for them.
