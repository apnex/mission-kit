### s0.Q1
The corpus names this as a fault: style/README.md "Faults" lists "**The forked enforcer.** Two tools holding one rule, disagreeing at the edges. This is why a rule names exactly one."
The remedy is in "Enforcement boundary": "An enforced rule names exactly one tool ... One rule, one tool, and that tool owns both the check and the fix, so a rule cannot be reported by one implementation and refused by another."
The pairing is declared in each rule's `enforced-by` frontmatter, and `tools/check-enforcers.sh` checks it in both directions: a rule naming a tool that does not exist fails, and so does "a per-rule tool no rule claims" (it reports "orphan tool").
So you resolve the conflict by keeping one tool as the rule's sole enforcer and folding in or deleting the other.
The corpus does not say how to decide which tool's edge behaviour is correct: NOT SETTLED.
GUESS: settle the edge cases against the rule's text in its style/Sn file, then keep the tool that matches it.
One limit: check-enforcers.sh only catches a second tool if it follows the `tools/s<N>-*` naming pattern. A second checker under another name would get past it. That is my inference from reading the script, not a claim the corpus makes.

### s0.Q3
No, not by default.
style/README.md "Enforcement boundary" says: "Style is gated on changed files rather than on the whole corpus. The corpus carries debt that predates the checkers, so gating the diff blocks new debt and converts the rest as sections are edited."
tools/check-all.sh does the same: "s6 s8 s10 s12 s13 s14 one sovereign checker per style rule, on changed files only". By default it compares against `origin/main`, and it also includes staged, unstaged and untracked `.md` files. If no markdown changed, it prints PASS for style.
A whole-corpus run exists only as an opt-in flag: `tools/check-all.sh --all` ("style over the whole corpus").
The non-style gates in check-all.sh (structure, enforcers, index, schemas and others) are not limited to the diff. The tools' own `*.test.sh` tests run "unconditional[ly]" over fixtures.

### s0.Q7
style/README.md "Faults" lists five unhealthy shapes:
- **The forked enforcer**: two tools hold one rule and disagree at the edges.
- **The orphaned rule**: a convention nobody enforces or reviews, "which teaches readers that the layer is decorative".
- **The unscoped medium**: rules for a non-document medium scattered among the document rules with nothing grouping them.
- **The work rule in style clothing**: a convention about what the work does or records, filed where an author will not look for it.
- **The corpus-wide sweep**: all legacy debt converted in one commit, producing a diff nobody can review.

"What earns an entry" adds a sixth shape by implication: rules admitted for aesthetic preference, or rules that hold inside only one document.
The "Axiom alignment" section names a current weakness: nine of fifteen rules are held only by reading, "so their hold is as strong as the review that reads for them".
