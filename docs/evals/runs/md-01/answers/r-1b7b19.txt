- D0 says a part splits only where portions are "proved differently", yet D5's own evidenceResolvesAgainst lists two clearly different contracts: source/PRs/CI, and WorkItem state/leases/graph topology. By D0's own criterion, D5 looks like a split candidate. D0 hedges this with "has been found needed" and "a part not yet split may be on the same terms", so Y3's answer depends on history rather than principle.
- D0 says "Two rows hold two domains, each because the evidence differs", but the control-plane row is split by machinery (two products), not by source vs state. That is a different reason from the product row's split, and the sentence blurs the two.
- No work-type covers revising an existing knowledge entry, or a fix with no filed bug. W2 requires a filed defect, so an engineer who simply finds and fixes a bug has no clean work-type.
- The governance machinery and the coordination machinery each own code that decides whether a merge is allowed (gates in D5, class-grants in D4). The corpus does not say how to place code that sits at their seam, for example class-grant checks implemented inside the coordination engine. The tie-break rule ("where its diff lands") then depends on which repository the code lives in, which the corpus does not define.
- D1's title here is "the shipped product's codebase". That differs from the D1 title in the INDEX I was given in standing context ("the product/service codebase"). I am noting it only; it did not affect these answers.
