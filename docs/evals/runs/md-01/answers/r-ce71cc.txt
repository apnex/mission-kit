### machinery-domain.Y3
D0 says each part of the organisation is an engineered product, and "A part's domain holds its source and its live state together" (domains/README.md, Territory).
A part splits into more than one domain "only where work on one portion is proved differently and the split has been found needed". The product's records were split this way: "The product's source resolves against code and CI, and its data against the records themselves, before and after."
D7 states the distinct evidence contract: "delivery-code holds the product's source; this domain holds what that source has written", and applying a migration is product-data while writing it is delivery-code (domains/D7-product-data.md).
D0 records how the split happened: product-data "entered" because work on records "had no domain", so it was added as a gap and not by stretching a neighbour.
For the control plane, D0 says "a coordination change, to its code or to the state of the work itself, resolves to coordination", and adds that "a part not yet split may be on the same terms".
So the corpus's reason is that no one has yet found the coordination split necessary. It does not give a principle that says the split is wrong.
NOT SETTLED: the corpus does not explain why coordination state is not "proved differently" from its code. D5 already lists "before/after graph topology" as evidence, which looks like D7's "records before and after".
