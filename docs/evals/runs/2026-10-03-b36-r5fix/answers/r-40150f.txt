### axiom-direction.Q1
The service is stateful and multi-agent, so `A1` (applies-to `stateful`) binds it alongside the multi-agent and `any-system` axioms (axioms/README.md, "Applicability matrix"). A component keeping important state only in process memory, where the other agents cannot see it, is exactly the gap `A1` names: "No functional unit possesses private, opaque, or transient truth" and fault "Hidden State Problem - state lives inside a process" (axioms/A1-sovereign-state-transparency.md). If your feature does not touch that component, A0 says "Beyond the scope, improvement is encouraged, never mandated". You are still "expected to weigh" fixing it, and may close it opportunistically, as "a change of its own", only if it is adjacent through a declared interface and passes `A14` tangent discipline: payback is near, the yield is captured, and the cost does not displace your goal (axioms/README.md; entities/E6-component.md "Adjacent against nearby"). Otherwise you record it "with its evidence and a revival trigger (`RU3`)". In every case "Passing it silently is what the axiom forbids" (axioms/README.md). For your own feature, "new work never repeats a gap the axiom names", so the feature's state goes into durable state other agents can query, not into process memory. If the feature newly depends on that component through a declared interface, the component is "touched but not altered, so its gaps must not be built on", so do not rely on its in-memory state. If the feature reaches into it with no declared interface, the two count as one system and "declaring and honouring the interface is inside its scope" (axioms/README.md; entities/E5-system.md "Boundaries").

### axiom-direction.Q2
In my own words: an axiom is a direction, not a checkbox. It names a limit ("asymptote") the system is built toward, and it constrains which way each change moves the system against that limit (axioms/README.md, "Standing commitment, not situated move"). The corpus states it as: "No change may move the system away from the limit, and each change moves it toward the limit as far as the change's own scope allows. ... never backwards, and forward with every step." A system "is not wrong for being short of it; it is wrong for moving away from it". The axiom is explicitly not a pass/fail test. A correction banner in the same file retracts the "invariants that hold or fail" reading, and the Faults list names that reading "The conformance reading", under which "no change advances the system". A gate stays binary only in the sense that it checks direction: "that the change moved the system no further from any limit in force, and repeated no gap it touched". Axioms are also conjunctive, so one may never be traded against another (axioms/README.md, "How the set composes").

### OBSERVATIONS
- axioms/README.md says a component that a change "newly depends on through a declared interface is touched but not altered ... and its axioms do not bind the change". But a component inside the same service is contained by that service, and E5 says a change answers to "every system containing it". So the service's `A1` still binds your change through the containing system. A reader could misread the A0 sentence as exempting the change from `A1`, and the text does not reconcile the two readings in one place.
- Whether a hidden-state component counts as "touched" depends on whether the feature reads or writes its state. The question does not settle this, so the answer covers both branches. NOT SETTLED for the specific case.
- A0 calls beyond-scope improvement "encouraged, never mandated" and in the next breath says the agent "is expected to weigh doing it, not merely permitted to". These can be reconciled (weighing is expected, acting is not), but the wording is close to self-contradictory.
- A0 routes unclosed gaps to `RU3`, but `RU3` is scoped to "parking, cutting or marking won't-do on a unit of tracked work". A newly noticed gap is not yet tracked work. Where to record it (backlog, defect record) is NOT SETTLED. GUESS: an `AR5` backlog row.
- "Either way the gap is recorded" (A0) follows a sentence about opportunistic changes, so it is ambiguous whether "either way" means closed-or-deferred or something else.
