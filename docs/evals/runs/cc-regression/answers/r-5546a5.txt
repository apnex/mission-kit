### s0.Q1
The corpus names this as a fault: style/README.md, Faults, "The forked enforcer. Two tools holding one rule, disagreeing at the edges. This is why a rule names exactly one."
The Enforcement boundary section says "An enforced rule names exactly one tool" and "One rule, one tool, and that tool owns both the check and the fix, so a rule cannot be reported by one implementation and refused by another."
The pairing is declared in each rule's `enforced-by` frontmatter and checked by tools/check-enforcers.sh: a rule naming a missing tool fails, and a per-rule tool (tools/s[0-9]*-*) that no rule claims fails as an "orphan tool".
So the remedy is to collapse to one tool, the one named in the rule's `enforced-by`, and remove the other.
NOT SETTLED: the corpus does not say how to choose which of the two tools survives.
Caveat (measured, from reading check-enforcers.sh): it only matches tools by the `sN-` filename prefix, so a second checker not named that way would not be caught as an orphan.

### s0.Q3
No, not by default. style/README.md, Enforcement boundary: "Style is gated on changed files rather than on the whole corpus. The corpus carries debt that predates the checkers, so gating the diff blocks new debt and converts the rest opportunistically as sections are edited."
tools/check-all.sh runs the per-rule checkers (s6 s8 s10 s12 s13 s14) on changed markdown only: committed against `origin/main` (or `--since REF`), plus staged, unstaged and untracked files; with no changed markdown the style step passes.
A whole-corpus run exists only by asking for it: `tools/check-all.sh --all`.
Also, only the six tool-held rules are checked at all; the nine reading-only rules are not gated by any script.
Non-style gates in check-all.sh (structure, enforcers, index, schemas, etc.) are not diff-scoped.

### s0.Q7
style/README.md, Faults, lists the unhealthy shapes: the forked enforcer (two tools holding one rule, disagreeing at the edges); the orphaned rule (nobody enforces and nobody reviews it, teaching readers the layer is decorative); the unscoped medium (rules for a non-document medium scattered among document rules with nothing grouping them); the work rule in style clothing (a rule about what work does or records, filed as style); the corpus-wide sweep (converting all legacy debt in one unreviewable commit).
From "What earns an entry", an unhealthy population would also include rules justified by aesthetic preference with no real defect, or rules scoped to one document.
The Axiom alignment section names current shortfalls: nine of fifteen rules held only by reading, and three claimed media (commit messages, code names, code comments) with no rule.
GUESS: the charter does not call those shortfalls "unhealthy" in so many words; it says reading-only rules are a stated property, not a backlog.

### OBSERVATIONS
- tools/README.md (Style gating paragraph) says "Changed means committed against the base plus staged plus unstaged", but tools/check-all.sh also includes untracked files (`git ls-files --others`). The README is stale on this.
- tools/check-all.sh repeats the comment line "Committed against the base, plus staged, plus unstaged." twice (an earlier version left in); tools/check-enforcers.sh likewise repeats the "six rules came to be enforced by one file holding six duties" sentence in two comments.
- tools/check-enforcers.sh finds orphan tools only by the `tools/s[0-9]*-*` filename glob, so a second checker for a rule with another name would not be flagged; the forked-enforcer guard is narrower than the charter's wording implies.
- The charter says a tool "owns both the check and the fix"; I did not verify that each of the six tools has a fix mode (NOT-CLAIMED). check-all.sh calls only the .mjs tool with `--check`.
- style/README.md says reading-only rules are "not a backlog", while its Axiom alignment section frames the same nine as falling short of A4; a mild tension, not a contradiction.
