### layer-charters.H5
A rule must declare `trace` in frontmatter: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md, "Member shape"). The schema enforces this. In `schemas/catalog-entry/v1alpha1/catalog-entry.schema.json`, if `category` is `rule` and the id matches `^RU[1-9][0-9]*$`, then `trace` is required (minLength 20). A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md). The optional field is `enforced-by`: "It names an enforcer in `enforced-by` when a tool checks it". `tools/check-enforcers.sh` checks that the named tool exists. "A rule with no tool yet is still a rule, and is checked by reading the trace" (RU0). The schema's `trace` description agrees: "Naming a tool that checks it is enforced-by's job, and is optional". The value must match `^tools/`.

### layer-charters.H6
`methods/README.md` (M0, "Placement") states the order once, and RU0 and PC0 cite it. Ask in order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? Then it is an axiom (`axioms/`).
2. Does following it produce a result of its own (a verdict, an artifact, a record)? Then it is a procedure/method (`methods/`). Guidance that only requires a record to carry something is a rule.
3. Does it govern how an artifact is written, its form, whatever the work was? Then it is style (`style/`).
4. Does it leave a trace in the record of the work that a check could test? Then it is a rule (`rules/`).
5. Otherwise it is a practice (`practices/`).

### OBSERVATIONS
- H7's premise fails if read strictly. No whole moment is empty in methods, rules and practices together. M10 covers handing over to a human, so only agent-to-agent or session-to-session handover has nothing governing it. The corpus never says in one place that a moment is empty in all three layers. That conclusion comes from joining three tables.
- M0's "Deciding what to keep" row says "none - gap" for procedures, but RU1 and RU3 hold that moment as rules. A reader who checks only M0 could wrongly think that moment has nothing governing it.
- `methods/M1-triangulated-review.md` heads its body "## Rule" even though it is a method. Its title says "minimum 4", but the rationale says "sometimes 3 is enough" and "below 3 the failure mode is predictable". Those statements disagree about the floor.
- `methods/README.md` lines 110-111: the "---" follows a text line with no blank line between them. In CommonMark that makes the line above a setext H2 heading, not a horizontal rule.
- PC1 sits at "Entering" in practices, but its trigger ("about to add an entry to a curated collection") is about authoring, not about beginning work. The placement is defensible but not obvious.
- In S0's territory table, the Document medium has no grain for headings. A heading-case rule would have to be placed under "section" or "token" by judgement.
