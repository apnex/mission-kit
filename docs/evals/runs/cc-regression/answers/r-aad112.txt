### component.C1
Y is outside the fix's mandatory scope: axioms/README.md (A0) says a change "touches what it modifies, what it newly depends on, and any consumer whose contract it alters", and X already called Y, so the fix neither modifies Y nor newly depends on it. Y is adjacent to X, in the closer direction: X stands on Y through a declared interface (entities/E6-component.md, "Adjacent against nearby": "the one the other stands on is the closer for compounding learning"). A0 says "Beyond the scope, improvement is encouraged, never mandated", and an agent that sees such an improvement "is expected to weigh doing it, not merely permitted to". The A14 tangent test (adjacent, yield captured, cost "does not significantly distract") looks met by a five-minute fix to friction that cost twenty minutes, so the corpus favours fixing Y "as a change of its own". That change answers to every system it alters, so if the error text is part of Y's interface, Y's consumers are altered too (A0; E5). For Z: X does not use Z, so the two share no declared interface, and E6 calls that "nearby and not adjacent". A two-day job would also "displace the goal". A0 therefore says Z's gap "is recorded with its evidence and a revival trigger (RU3) rather than closed", and the choice of next work is the director's (R4, AR3). "Either way the gap is recorded. Passing it silently is what the axiom forbids" (A0). GUESS: hidden important state probably makes the service stateful (traits/T1-stateful.md), which brings A1's "Hidden State Problem" into force for the containing service, but your fix still only has to avoid making Z's gap worse or building on it.

### component.C2
The corpus defines it in entities/E6-component.md: "A component is a system seen as a part of a larger system that contains it", with "one duty" at that altitude, and it "exposes and consumes interfaces". "Every component is a system; component names its place in a containing system, not a different kind of thing." The difference is which question you are asking: "Traits, axioms and what a change answers to are questions about a system. Duty, interfaces, neighbours and blast radius are questions about a component" (E6 Discriminators; also entities/E5-system.md, "A system against a component"). A system that nothing contains "is not a component of anything" (E6). E6 also says a component is not a file, module, package, repo or deployable by definition, not a SysML part, and not necessarily registered in components/.

### component.C3
No. E6 says "A component's directory addresses it ... Its boundary is its declared interfaces", and E5 says a directory "is the boundary of neither the system nor the component". Nothing declares an interface here, so for deciding what a change answers to, parts/thing and the code in parts/other that reaches into it are "one system, with the traits of both" (E5 Boundaries; E6 Definition). What is wrong: the undeclared dependency "is itself a fault against A3", which requires units to "interact only through declared adapters and contracts; no unit reaches into another's internals" (axioms/A3-sovereign-composition.md, Air-Gap Principle). The fix is to declare the interface and move the dependency onto it, which "is what makes them two again" (E5). A change that alters what parts/other reaches into "owns that boundary: declaring and honouring the interface is inside its scope, not optional" (E5). GUESS: A3's "Bypass as Signal" (evaluate the interface against the component's duty) strictly covers reaching past a declared interface. By analogy, though, what parts/other needs should shape the interface you declare.

### component.C4
Your change answers to P and to every system containing P, which here is the service (A0: "the system it modifies, every system containing it, and any system whose contract with it the change alters"). The service "has every trait any part it contains has" (E5), so the axioms that Q's traits bring in also reach your change, but through the containing service. They do not reach it because Q was altered. Q is not altered: E6's blast-radius row says a change reaches "an adjacent component only if the interface between them changes", and A0 says a system whose contract is left as it was "is not altered". Q is not in the change's scope either, because you did not modify it, newly depend on it, or alter its contract. Q is adjacent to P, because they share a declared interface (E6), so Q is a candidate for opportunistic improvement under A0/A14. But Q stands on P, not P on Q, so this is "adjacency with less payback, not none" (E6). Any such improvement would be a separate change, recorded either way.

### OBSERVATIONS
- A0 lists "what it newly depends on" as touched, but says nothing about a dependency the change already had, like X on Y. I treated an existing dependency as not touched. NOT SETTLED by explicit text.
- Whether an error message's wording is part of Y's declared interface is NOT SETTLED. If consumers parse it, E5 calls that "parsing output the interface does not promise", which would make them one system with Y.
- C4 tension: A0 says a system it "only composes with" is not bound. But P and Q both sit inside the service, and E5 says the containing system carries every part's traits. So Q's axioms bind through the service even though Q is unaltered. Neither A0 nor E5 states this case directly.
- A3's "Bypass as Signal" is worded for reaching past a declared interface. C3's case, where no interface exists at all, falls under E5 Boundaries instead, and the remedy procedure is less specific there.
- The corpus does not mention A10, which is tagged multi-agent/autonomous only, for a plain service. Whether it applies to C1's friction depends on traits the question does not give.
