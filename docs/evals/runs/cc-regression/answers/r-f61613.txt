### layer-charters.H1
It belongs in rules/ (RU). methods/README.md (M0) gives placement as five ordered questions and uses this as its own example: "*credentials are never committed* binds an action in a situation, and is a rule". It is not an axiom, because question 1 asks about "a limit a system is built toward" and not about "how universal a ban sounds". It produces no result of its own and does not govern an artifact's form. It leaves a trace a check could test, because every commit shows it. rules/README.md confirms this under "Gaps tested": "*Treating the record:* credentials are never committed - `M0`'s own example of a rule". So it is a candidate for the "Treating the record" moment, and no RU entry holds it yet. As a rule entry it must declare a `trace` (rules/README.md "Member shape").

### layer-charters.H2
It belongs in practices/ (PC). By M0's order: it is not an axiom, it produces no verdict, artifact or record, and it does not govern an artifact's form. A re-read leaves nothing in the record, so question 4 (trace) gets "no" and question 5 makes it "a practice". practices/README.md defines a practice as guidance that "leaves no trace: nothing in the record afterwards shows whether it was followed". The nearest moment is "Verifying", and practices/README.md lists that row as "none - gap". Placement is not admission, though. ### layer-charters.H4
It belongs in style/ (S). It governs how an artifact is written, "its form, whatever the work was" (M0 question 3). style/README.md says "A style rule governs an artifact's form, and is judged by reading the output". It fits the Document medium at the "section" grain, or possibly the "token" grain. No current member (S1-S15) covers heading case. Placement alone does not earn an entry. S0 also requires that "Its absence produced a real defect in a real artifact" and that it "holds across artifacts". S0 says "Prefer a rule a script can hold", and heading case can be stated as a predicate over the text, so it would probably name an `enforced-by` tool. Aesthetic preference alone "does not qualify".

### layer-charters.H5
A rules/ entry must declare `trace` in its frontmatter: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md "Member shape"). schemas/catalog-entry/v1alpha1/catalog-entry.schema.json enforces this: when `category` is `rule` and `id` matches `^RU[1-9][0-9]*$`, `trace` is required (minLength 20). A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md). Optionally, a rule may name the tool that checks it in `enforced-by` (pattern `^tools/`), and `tools/check-enforcers.sh` checks that the tool exists. The schema's `trace` description says "Naming a tool that checks it is enforced-by's job, and is optional". A rule with no tool "is still a rule, and is checked by reading the trace".

### layer-charters.H6
methods/README.md (M0) says to ask the questions in order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? -> axiom (axioms/).
2. Does following it produce a result of its own (a verdict, an artifact, a record)? -> method (methods/). Guidance that only requires a record to carry something is not a method; it is a rule.
3. Does it govern how an artifact is written, its form, whatever the work was? -> style (style/).
4. Does it leave a trace in the record of the work that a check could test? -> rule (rules/).
5. Otherwise -> practice (practices/).
rules/README.md, practices/README.md and style/README.md all cite this as "axiom, procedure, style, rule, practice, asked in that order".

### layer-charters.H7
Handing over work in progress to another agent or to a later session. M0 says: "*Handing over* holds `M10`, which hands understanding and decisions to a human; handing work in progress to another agent or a later session has no procedure at all". rules/README.md lists "Handing over" as "none - gap" ("a handover record names what is unfinished - a rule that would leave a trace, and none exists"). practices/README.md also lists "Handing over" as "none - gap". M0 says this is where being cold matters most: "a lone agent hands over to its own next session". Note: if you read only the three moment tables, every moment has at least one member in some layer. Handing over is non-empty only because of M10, which covers handover to a human. So the moment with nothing governing it is the agent-to-agent or agent-to-later-session handover.

### OBSERVATIONS
- H7 is ambiguous at the level of whole moments. Compare the three territory tables: no moment is empty in all three layers. Methods is empty only at "Deciding what to keep", and RU1/RU3 fill that moment in rules. The only gap with nothing at all is the agent and later-session part of "Handing over", which M0's prose states.
- M1 is in methods/ but its body heading is "## Rule". The superseded M3-M6 entries were moved out of methods because they were rules or practices, so this heading may confuse placement. PC1 (a practice) also uses "## Rule" as its heading. README.md "Adding an entry" says body sections stay close to "rule, rationale, examples, and when to apply", so this is the generic skeleton, but it conflicts with the rule/practice/method vocabulary.
- README.md calls INDEX.md "the flat ledger across every category", but INDEX.md is grouped by layer. INDEX.md also says Links resolve from "a local mission-kit checkout... otherwise fetch from" GitHub, which reaches outside this corpus snapshot.
- The catalogue schema requires `trace` for rules. I found nothing in the schema that forbids a practice from declaring `trace`; PC0 states the prohibition only in prose. This is inferred from the parts of the schema I read, not from a full read.
