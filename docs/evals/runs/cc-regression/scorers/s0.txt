Question:
Two tools both check the same style rule and disagree at the edges. What does the corpus say?

Key:
One rule, one tool: a rule names exactly one enforcer, which owns both the check and the fix; two tools holding one rule is the forked-enforcer fault.

Rubric:
2 for one rule one tool with the fault. 1 for one rule one tool alone. 0 otherwise.

--- answer a-81b1b900 ---
The corpus names this exact case as a fault: style/README.md, Faults: "The forked enforcer. Two tools holding one rule, disagreeing at the edges. This is why a rule names exactly one."
The remedy is in the Enforcement boundary section: "An enforced rule names exactly one tool ... One rule, one tool, and that tool owns both the check and the fix, so a rule cannot be reported by one implementation and refused by another."
The pairing is declared in each rule's `enforced-by` frontmatter and verified by tools/check-enforcers.sh, which fails if a rule names a non-existent tool or if a per-rule tool (tools/s[0-9]*-*) is claimed by no rule.
So the answer is to collapse to one tool, which the rule names in `enforced-by`, and retire the other.
Limit: check-enforcers.sh catches an unclaimed `sN-*` tool, but I found nothing that would catch a second checker for the same rule that is named differently or lives elsewhere. NOT SETTLED whether such a fork would be detected mechanically. GUESS: it would not be.
