### layer-charters.H1
It belongs in `rules/` (RU). The corpus uses this exact case as its worked example: methods/README.md (M0), Placement: "*credentials are never committed* binds an action in a situation, and is a rule."
M0 also says question 1 (axiom) "is about a system's properties, not about how universal a ban sounds", so it is not an axiom even though it sounds absolute.
It produces no result of its own (not a method), and it governs what the work does, not an artifact's form (not style). It leaves a trace a check could test (rules/README.md: "leaves a trace a check could test: something in the record of the work shows whether it was kept"). Here the record is the repository content itself.
As a rule it would have to declare a `trace` in frontmatter (rules/README.md, Member shape).
No existing entry holds it: RU1-RU4 cover default-reject, frozen history, deferral and publishing rewritten history. M9 (history content scrub) is the procedure for removing content after it has been committed, not the rule against committing it.
GUESS: the trace would be something like "no credential material appears in any committed tree", and a secret scanner could be named in `enforced-by`.

### layer-charters.H2
It belongs in `practices/` (PC).
Take the M0 placement questions in order. It is not a limit a system is built toward (1). Re-reading produces no verdict, artifact or record (2). It does not govern an artifact's form (3). Nothing in the record shows whether the re-read happened (4).
That leaves 5, "Otherwise a practice" (methods/README.md). practices/README.md defines a practice as guidance that "leaves no trace: nothing in the record afterwards shows whether it was followed."
Its moment would be *verifying*, which practices/README.md lists as a gap: "*Verifying*, *deciding what to keep* and *handing over* hold no practice today."
Placement is not admission. PC0 says "admission says whether it has earned an entry, which takes observed evidence", and "A practice is not minted to fill a moment."
So it would be a practice, but it earns an entry only once following it has been observed to produce measurably different work. No such evidence is in the corpus, and no entry covers it now.

### layer-charters.H3
It belongs in `methods/`. Following it produces a result of its own, a verdict, which is placement question 2 in M0 ("Does following it produce a result of its own - a verdict, an artifact, a record? A procedure, here").
An entry already covers it: methods/M1-triangulated-review.md, "Triangulated review - minimum 4 independent inputs". Its hydrate-when is "You are reviewing a patch or design that ships to production or upstream."
M1's Rule section says: "require **at least four genuinely independent inputs** before reaching a verdict". The canonical four are upstream baseline, prior-version intent and review, archaeology, and community signal.
M1 also requires the comparison step: "force the reviewer to reconcile multiple framings of the same surface. The reconciliation is where real bugs surface."
M0 places M1 at the *verifying* moment and calls it "One primitive carries the set".
So you would strengthen M1 rather than add a neighbour (M0: "Prefer strengthening an existing entry to adding a neighbour").

### layer-charters.H4
It belongs in `style/` (S). It governs how an artifact is written, its form whatever the work was, which is M0 placement question 3. Style is "Rules about the artifact itself, judged by reading the output rather than by watching it being produced" (style/README.md).
No current entry covers heading case: S1-S15 cover prerequisites, code blocks, READMEs, version pins, line breaks, backticks, ASCII, triggers, messages and so on.
To earn an entry, S0 requires that "its absence has produced a real defect in a real artifact". It also says "Aesthetic preference does not qualify."
S0 says to "Prefer a rule a script can hold". Heading case can be stated as a predicate over the text, so it should get one tool named in `enforced-by`.
NOT SETTLED: whether sentence-case headings have caused a real defect. The corpus records no such defect, so as proposed this may fail admission as aesthetic preference.

### layer-charters.H5
A rule must declare `trace` in frontmatter: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md, Member shape).
The schema makes this mechanical. schemas/catalog-entry/v1alpha1/catalog-entry.schema.json has an if/then: category `rule` with id `RU[1-9]...` requires `trace`.
A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md).
Optionally, a rule may name an enforcer in `enforced-by` "when a tool checks it". `tools/check-enforcers.sh` then holds that tool to existing. The schema describes it as "Naming a tool that checks it is enforced-by's job, and is optional."
"A rule with no tool yet is still a rule, and is checked by reading the trace" (RU0).

### layer-charters.H6
Placement is stated once, in methods/README.md (M0), and cited by RU0 and PC0. Ask in order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? Then it is an axiom (`axioms/`).
2. Does following it produce a result of its own (verdict, artifact, record)? Then it is a method/procedure (`methods/`). Guidance that only requires a record to carry something is a rule.
3. Does it govern how an artifact is written, its form whatever the work was? Then it is style (`style/`).
4. Does it leave a trace in the record of the work that a check could test? Then it is a rule (`rules/`).
5. Otherwise it is a practice (`practices/`).
RU0 sums this up as "axiom, procedure, style, rule, practice, asked in that order."

### layer-charters.H7
Handing work over to another agent or to a later session.
M0 says: "*Handing over* holds `M10`, which hands understanding and decisions to a human; handing work in progress to another agent or a later session has no procedure at all."
RU0 says no rule covers handing over: "A rule for handing over - *a handover record names what is unfinished* - would leave a trace, and none exists."
PC0 lists *handing over* among the moments that "hold no practice today."
Caveat: strictly, none of the six named moments is completely empty, because M10 sits at *handing over*. What is empty is the agent/session side of handover.
M0 notes this is where "that condition bites hardest", since "a lone agent hands over to its own next session."

### OBSERVATIONS
- H7 premise: no whole moment is ungoverned by all three layers. Procedures cover five moments; *deciding what to keep* has no method but has RU1 and RU3, and *handing over* has M10. The fully empty part is handover to an agent or later session, which is a sub-part of a moment. I answered on that reading.
- practices/README.md "Gaps tested" lists only verifying, deciding what to keep and handing over. But by its own table, *committing to a design* and *treating the record* also hold no practice; only *entering* (PC1) is filled. The gap list is incomplete or inconsistent.
- M1's title says "minimum 4", but its Rationale says "The number isn't sacred (sometimes 3 is enough; sometimes 5 is needed)" and "below 3 the failure mode is predictable". That is a soft internal tension between a floor of four and a floor of three.
- M1 and PC1 use a body heading "## Rule", although M1 is a method and PC1 is a practice. This is legacy skeleton naming that clashes with the new rules/practices split.
- INDEX.md says links resolve against a checkout "otherwise fetch from https://raw.githubusercontent.com/apnex/mission-kit/main/". I did not fetch anything and used only the local corpus.
- The README.md Mechanics row says INDEX.md is "the flat ledger", while INDEX.md is grouped by layer. This is minor wording drift.
