### OBSERVATIONS
- W0 constraint 2 says that if the roster collapses attester and executor, "fail the seed or downgrade to kind:review" (W8's body repeats this), while constraint 9 and R0 say "Same-agent review is never a valid degradation". As written, "downgrade to kind:review" could be read as letting the same agent review its own work. Presumably it means a review by a different identity, but the text does not say so.
- No text says which governs if a trait entry's "Axioms it brings into force" list disagrees with applies-to. A0's "only field" settles it by inference. tools/check-traits.mjs checks only the applies-to enum against the trait names, not the per-trait axiom lists, so those lists could drift without any check failing.
- W7's title and body ("release artifact", "estate/channel") never mention data or migrations. Only D7 and W7's domainEligibility tie migration-apply to W7.
- D1's A1 "axiom alignment" could be misread as A1 binding every codebase. D0/A0 rule that out, but D1 itself gives no hint.
- D3 names specific tools ("ois/pi/claude launchers"), which D0 already lists as a known fault.
- INDEX.md says to resolve links against a remote GitHub URL when there is no local checkout. This eval forbade reading outside the corpus, so I used only the local copy.
