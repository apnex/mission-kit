### composition.P1
Traits: stateful (T1 test: "writes something it will later read back"), multi-agent (T3: "two or more independent actors coordinate over shared substrate"), llm-in-the-loop (T5: "would the system decide or act differently if the model's output were different"); a long-running service operated by agents very likely also passes T4 autonomous, and it is not declarative unless it reconciles toward a declaration (T2).
Rule: axioms/README.md (A0) "An axiom is in force for a system if, and only if, that system's architecture satisfies at least one of the axiom's applies-to tags", and traits/README.md (T0) "a system's obligations are the union of every axiom any of its traits brings into force, plus every axiom on the floor".
Floor (any-system): A3, A4, A8, A9, A14; stateful: A1; multi-agent: A5, A6, A7, A10, A13; llm-in-the-loop: A5, A11, A12; autonomous adds nothing new (A7, A10, A13).
Result: A1 and A3-A14 - thirteen axioms; A2 binds only if the service is declarative (T2), which the question does not settle.
I determined this from each axiom's `applies-to` frontmatter (axioms/A*.md line 7), which A0 says "is the only field that does" decide binding, cross-checked against the A0 applicability matrix and the T1/T3/T5 "Axioms it brings into force" lists, which all agree.

### composition.P2
The formatter fails every trait test: not stateful (T1 "Not stateful: a pure function"), not declarative (T2 "Not declarative: a script run once"), not multi-agent (T3 "a single agent working alone"), not autonomous (T4 "an interactive session" - a person runs it), not llm-in-the-loop (T5).
So only the floor binds: A3, A4, A8, A9, A14 (A0 matrix: "a plain library takes any-system"; E5: "A one-shot script with no traits is a system, bound by the axioms every system carries").
A1 does not constrain this work: A0 says "applies-to answers whether an axiom binds, and it is the only field that does", and A1's applies-to is [stateful], which the formatter lacks.
D1's citation of A1 states what A1 demands on the delivery-code surface when it binds; D0/A0 say "a domain entry cites the axioms it must satisfy" and "applies-to decides whether ... the domain decides what it demands on that surface".
Traits are tested on the system, not the task (E5: "A trait's test is applied to a system, never to a task"), so my being an LLM agent does not make the formatter llm-in-the-loop (T5: "built with model assistance ... The model was in the authoring loop").
Caveat: if the formatter shares an undeclared boundary with a stateful system, E5/A0 make them "one system, with the traits of both", and A1 would then bind.
