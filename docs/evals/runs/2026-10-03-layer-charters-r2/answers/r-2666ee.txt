### layer-charters.H4
The layer is `style/`. S0 says style holds "Rules about the artifact itself, judged by reading the output rather than by watching it being produced". M0's discriminating question puts the same test this way: "If they would read the output, it is style."
No existing S entry covers heading case. S1-S14 cover other conventions.

### layer-charters.H5
Measured from `schemas/catalog-entry/v1alpha1/catalog-entry.schema.json`: an entry with `category: rule` and an id matching `^RU[1-9][0-9]*$` must declare `trace` (minLength 20), "the observable trace a check could test". A practice has no such requirement, because "a practice leaves none". `schemas/tests/catalog-entry/catalog-entry.test.mjs` confirms that a rule without `trace` is refused and that `PC1` with no `trace` is accepted.
Optionally, a rule may declare `enforced-by` naming a tool under `tools/`. The `trace` description says "Naming a tool that checks it is enforced-by's job, and is optional". `tools/check-enforcers.sh` scans `rules/RU*.md` and checks that any named enforcer exists.
Both kinds share the base required fields: `id`, `category`, `title`, `status`, `hydrate-when`.
Caveat: no `rules/` or `practices/` directory or charter (`RU0`/`PC0`) exists in this corpus. This answer comes only from the schema, its tests and one tool.

### layer-charters.H6
NOT SETTLED. No file in the corpus gives an ordered set of questions across axiom, method, style, rule and practice. I searched the charters, the entities and the schema.
GUESS, assembled from separate texts:
(1) Is it declinable? If it is always in force, it is an axiom. A0: "it is not declinable, so it is not a move" (M0 table), standing commitment against situated move.
(2) If it is a situated move, would a reviewer judge it by reading the output? If so, it is style. If they would need to know how you arrived at it, it is conduct (M0 discriminating question).
(3) For conduct, does it leave an observable trace in the record? If so, it is a rule (`RU`, schema `trace` description). If not, it is a practice (`PC`).
Where "method" sits against rule and practice is not stated anywhere. The schema accepts both `method` and `methodology` as categories without defining either.

### layer-charters.H7
**Handing over**: passing work in progress to another agent or a later session. `methodology/README.md` (M0) Territory says it "has no procedure at all", and adds that "a lone agent hands over to its own next session".
M0 states this only as an absence of procedure. Rules and practices cannot govern it either, because those layers do not exist in this corpus. So "nothing at all" holds by default, not because the text says so.
Contrast this with the other thin moment, *Committing to a design*. It does hold one member, M7, which is scoped to extensive design.

### OBSERVATIONS
- The questions assume `rules/` and `practices/` layers, but none exists here. They are missing from the directory tree, the README.md `Mechanics` table and INDEX.md, and there are no `RU0`/`PC0` charters. Only the schema (enum `rule`, `practice`, `method`; prefixes `RU`, `PC`), the schema tests ("Delta-1 stage 1") and `tools/check-enforcers.sh` (`rules/RU*.md`) refer to them. This is a half-landed transition.
- The schema enum has both `methodology` and `method`, and the test accepts `M9` as `method`. Neither the M0 charter nor E2 mentions `method`, and its relation to `methodology/` is undefined.
- The schema's top-level `description` still lists eight categories, but the enum holds seventeen.
- The README.md `Mechanics` table links `docs/`, which does not exist in this corpus.
- VISION.md mentions "the rules and practices that hold inside them", and no layer backs that.
- M0 says handover "has no procedure at all". The question's wording, "no procedure, rule or practice", goes further than the text.
