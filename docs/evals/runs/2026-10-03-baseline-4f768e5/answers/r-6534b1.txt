But Y is adjacent: X consumes Y's declared interface, and Y is the one X "stands on", which `entities/E6-component.md` calls "the closer for compounding learning". ### component.C2
`entities/E6-component.md` defines it: "A **component** is a system seen as a part of a larger system that contains it". It has "one duty" at the altitude where it appears as a part, and it "exposes and consumes interfaces". "Its boundary is those interfaces." A system is defined in `entities/E5-system.md` as "a unit of engineering with a boundary", which "traits describe" and "axioms bind". The difference is not a difference in kind: "Every component is a system; *component* names its place in a containing system, not a different kind of thing." To tell them apart, E6 says to "Ask what question is being answered". Traits, axioms and what a change answers to are questions about a system, while "Duty, interfaces, neighbours and blast radius are questions about a component". "A system nobody contains ... is not a component of anything". A component also does not need to be registered in `components/` (C0): "Most components are never registered".

### component.C3
No. E6 ("Boundary against directory") says: "A component's directory addresses it ... Its boundary is its declared interfaces". It adds that "with no declared interface there is no boundary to cross". E5 agrees that a directory "is the boundary of neither the system nor the component". So parts/thing/ is still a component, but "nothing separates it yet". For deciding what a change answers to, it and parts/other/ are "one system, with the traits of both" (E5 *Boundaries*; E6 Definition). A change to thing's internals reaches other (E6 blast-radius row: "any unit that reaches it ... with no declared interface"). The defect is the undeclared dependency itself: "The undeclared dependency is itself a fault against A3" (E5). It breaks A3's Air-Gap Principle: "no unit reaches into another's internals". The remedy is to declare an interface, because "Declaring its interfaces is what separates it" (E6), and parts/other/ is the "real consumer" that A3's Earned Exposure requires.

### component.C4
Your change answers to P, the system it modifies, and to "every system containing it", which is the service (A0, "An axiom binds a system..."). Q is not altered. Q composes with P "through a contract the change leaves as it was", so it "is not altered, and its axioms do not bind" (A0). E6's blast-radius row agrees: a change reaches an adjacent component "only if the interface between them changes". Q is adjacent, because adjacency means sharing a declared interface "in either direction" (E6). So Q is a candidate for opportunistic improvement: A0 allows a component "one it stands on, or one that stands on it". Q stands on P, so this is the direction E6 calls "adjacency with less payback, not none", and A14's test still applies. Caveat from E5: if Q relies on undeclared behaviour of P, that is "a contract in fact" and "a change to it reaches across". The question rules this out by saying the behaviour is unchanged.

### OBSERVATIONS
- A0 says a change "touches ... what it newly depends on". It does not say whether an existing dependency that you used while debugging (Y in C1) is touched. I treated Y as untouched but adjacent. NOT SETTLED.
- The corpus does not say whether an error message's text is part of a declared interface. If it is, making Y's message precise alters Y's contract, and under A0 that change then also answers to Y's other consumers. NOT SETTLED.
- C1: the corpus does not settle whether the service is stateful, so A1 is in force only if the service passes T1's test ("would anything act differently if that record were wrong?"). The question does not settle that test either.
- The components layer charter (C0) is titled "sovereign shareable substrates", while E6 defines "component" much more broadly. E6 states the distinction explicitly, but the layer name keeps the older sense alive.
- E5 says a module "is a system, and the service contains it, whether or not the module's interfaces are declared". It also says units with an undeclared boundary are "one system". Both can apply together, but E5 does not explain how containment and this collapse interact.
