### layer-charters.H1
`rules/` (RU). Use the placement order in `rules/README.md` ("Ask in order, and stop at the first yes"). It is not "in force regardless of situation": it binds only when you commit, so it is a situated move, and A0 names "a tactical rule promoted for importance" as a fault. Following it produces no "verdict, an artifact, a record", so it is not a method. It does not govern "how an artifact is written - its form", so it is not style. It does "leave a trace in the record of the work that a check could test": the repository history either holds a credential or it does not. So it is a rule. As an RU entry it must declare a `trace`, and it may name a `tools/` scanner in `enforced-by` (RU0 "Member shape"). Removing a credential after it has been committed is a different item: that is K1 (history content scrub), a procedure moving to methodology's "Correcting the record". GUESS: the nearest rules territory row is "Treating the record", but no row clearly covers preventing content from entering the record.

### layer-charters.H2
`practices/` (PC). In the five-question order it is not an axiom, it produces no result of its own, and it does not govern an artifact's form. Re-reading the request "leaves no trace": PC0 says "nothing in the record afterwards shows whether it was followed", so it is not a rule. It falls in the *Verifying* moment, which PC0 records as holding "no practice today". It is admitted only "by evidence that following it produces measurably different work" (PC0 Purpose). Without that evidence it is "The unevidenced practice ... it is a proposal" (PC0 Faults). The corpus records no such evidence for this guidance, so whether it can be admitted now is NOT SETTLED.

### layer-charters.H3
`methodology/` (M). The guidance produces a result of its own, a verdict, and M0 places verifying procedures there ("Verifying | what evidence is enough to believe the work is correct | M1, M2"). Yes, an entry already covers it: `methodology/M1-triangulated-review.md` requires "at least four genuinely independent inputs before reaching a verdict". Its trigger is "Reviewing patches or designs that ship to production or upstream". M0 calls M1 the primitive "the verifying procedures specialise". Do not add a neighbouring entry. M0 says "Prefer strengthening an existing entry to adding a neighbour".

### layer-charters.H4
`style/` (S). It governs "how an artifact is written - its form, whatever the work was" (third placement question, RU0/M0). S0 also says style holds "Rules about the artifact itself, judged by reading the output". No existing S1-S14 entry covers heading case: I searched for "sentence case" and "title case" and found nothing. Being in the right layer does not earn it an entry. S0 says a convention earns one only "when its absence has produced a real defect in a real artifact", and "Aesthetic preference does not qualify". If it is admitted, S0 says to state it as a predicate and write the tool, declared in `enforced-by`. The corpus records no such defect, so whether it should be admitted is NOT SETTLED.

### layer-charters.H5
A rule must declare `trace`: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (RU0 "Member shape"). The schema makes `trace` required for category `rule` with IDs `^RU[1-9]...`, and it must be at least 20 characters (`schemas/catalog-entry/v1alpha1/catalog-entry.schema.json`). A practice "declares no `trace`; if it acquires one, it is a rule and moves" (PC0). Optionally, a rule may name an enforcer in `enforced-by`, a path matching `^tools/`, "when a tool checks it". `tools/check-enforcers.sh` checks that the named tool exists. A rule without an enforcer "is still a rule, and is checked by reading the trace" (RU0). The schema's `trace` description agrees: "Naming a tool that checks it is enforced-by's job, and is optional."

### layer-charters.H6
Ask these in order and stop at the first yes (RU0 "Placement", repeated in PC0 and M0):
1. Is it in force regardless of situation? Then it is an axiom.
2. Does following it produce a result of its own (a verdict, an artifact, a record)? Then it is a method, in `methodology/`.
3. Does it govern how an artifact is written, its form, whatever the work was? Then it is style, in `style/`.
4. Does it leave a trace in the record of the work that a check could test? Then it is a rule, in `rules/`.
5. Otherwise it is a practice, in `practices/`.
Question 3 is about the object, not about whether it can be checked. "Every deferral records its revival trigger" is still a rule.

### layer-charters.H7
*Handing over*: passing work in progress to another agent or to a later session. M0 says handing over "has no procedure at all". RU0 lists it among the moments that "hold no rule today", and adds that "a handover record names what is unfinished" would leave a trace, "and none exists". PC0 says "*Verifying*, *deciding what to keep* and *handing over* hold no practice today". Handing over is the only moment that all three charters record as empty. Verifying has M1 and M2, and deciding what to keep has M3 and M5 as rules.

### OBSERVATIONS
- M0 says the procedures "fall at five moments", but its table has four rows (Entering, Committing to a design, Verifying, Correcting the record). Handing over is only mentioned in prose. The rules and practices charters use a different moment list: they have "Deciding what to keep" and "Treating the record" but not "Correcting the record". So the set of moments is not stated the same way in the three charters.
- "Entering" appears in both methodology (M8) and practices (M6). That is consistent with the rule "every member in exactly one moment" per set, but the moment is shared across sets.
- M1's body heading is "## Rule", although M1 is a method. The ledger, M0 and the directories still list M3, M4, M5, M6 and K1 in their old layers, pending "Delta-1's stage 3". `rules/` and `practices/` hold only their charters.
- The catalogue schema's top-level description lists categories without rule or practice, but its enum includes both.
- M0's "How the procedures compose" section has no blank line before its closing `---` (line 97-98).
- A0 lists the tactical layers as `S`/`M`/`P`/`K`, which leaves out the new RU/PC layers.
