### layer-charters.H5
A rule must declare `trace` in frontmatter. This is "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md, Member shape).
The schema makes `trace` required when category is `rule` with an RU id. Its description (schemas/catalog-entry/v1alpha1/catalog-entry.schema.json) reads: "A rule earns its layer by leaving one; a practice leaves none." It needs at least 20 characters.
A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md).
Optionally, a rule may declare `enforced-by`, naming the tool that checks it (pattern `^tools/`). `tools/check-enforcers.sh` holds that tool to existing. "a rule with no tool yet is still a rule, and is checked by reading the trace." The schema: "Naming a tool that checks it is enforced-by's job, and is optional."

### layer-charters.H6
methods/README.md (M0), "Placement", says to ask in order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? Then it is an axiom (axioms/).
2. Does following it produce a result of its own - a verdict, an artifact, a record? Then it is a procedure (methods/). Guidance that only requires a record to carry something is a rule.
3. Does it govern how an artifact is written - its form, whatever the work was? Then it is style (style/).
4. Does it leave a trace in the record of the work that a check could test? Then it is a rule (rules/).
5. Otherwise it is a practice (practices/).
rules/README.md and practices/README.md both cite this order: "axiom, procedure, style, rule, practice".

### layer-charters.H7
Handing work in progress over to another agent or to a later session. M0 (methods/README.md): "*Handing over* holds `M10`, which hands understanding and decisions to a human; handing work in progress to another agent or a later session has no procedure at all."
rules/README.md: "A rule for handing over - *a handover record names what is unfinished* - would leave a trace, and none exists." practices/README.md: "*Handing over* hold[s] no practice today."
So no procedure, rule or practice governs it. The *handing over* moment as a whole is not empty, because M10 covers handover to a human. Of the six moments, only handing over has no procedure, rule or practice for the agent/session case.
M0 adds: "a lone agent hands over to its own next session".

### OBSERVATIONS
- practices/README.md "Gaps tested" lists only verifying, deciding what to keep and handing over as holding no practice. By its own table, *committing to a design* and *treating the record* also hold no practice, so that list is incomplete.
- H7: no moment is empty as a whole. Every one of the six has at least one member in some layer, and handing over has M10. The "nothing at all" gap is only the agent-or-later-session handover sub-case.
- M1 is titled "minimum 4 independent inputs" and calls four "the empirical floor". Its Rationale then says "sometimes 3 is enough" and that "below 3 the failure mode is predictable", which blurs the floor.
- M1 and PC1 both use a "## Rule" body heading even though one is a method and one is a practice. M0's placement table header also says "If the rule governs" in a generic sense. This loose use of "rule" conflicts with the rules/ layer's technical meaning.
- M0 says procedures "sit at five of the six" moments. The missing one is *deciding what to keep*, which is held only by rules RU1/RU3. That is consistent, but it is not stated explicitly.
- None of RU1-RU4 declares `enforced-by`, so every current rule is held only by reading its trace.
