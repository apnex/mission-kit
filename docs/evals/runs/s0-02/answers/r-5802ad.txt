### s0.Q1
The corpus names this exact case as a fault. style/README.md (S0), Faults: "The forked enforcer. Two tools holding one rule, disagreeing at the edges. This is why a rule names exactly one."
The remedy is in S0 "Enforced and unenforced rules": an enforced rule "declares `enforced-by` in its frontmatter naming exactly one tool", and "One rule, one tool, and that tool owns both the check and the fix, so a rule cannot be reported by one implementation and refused by another."
tools/check-enforcers.sh holds the pairing both ways: a named tool must exist and be executable, and each per-rule tool `tools/s[0-9]*-*` must be claimed by a rule.
tools/lib/style-common.sh records the history: restating shared logic "was how the S6 boundary rule came to exist in four places that disagreed."
So: pick the one tool the rule's `enforced-by` names, and remove or delegate the other check.
Limit: check-enforcers.sh only looks at tools named `tools/s<N>-*`, so a second checker under another name is not detected (see OBSERVATIONS for a live S13 case).

### s0.Q3
No. style/README.md: "Style is gated on changed files rather than on the whole corpus... gating the diff blocks new debt and converts the rest opportunistically as sections are edited."
tools/check-all.sh confirms this. The default runs the per-rule checkers (s6 s8 s10 s12 s13 s14) "on changed files only". "Changed" means committed against the base, plus staged, unstaged and untracked files, filtered to `\.md$`.
A whole-corpus run exists only as an opt-in flag: `tools/check-all.sh --all`.
CI (.github/workflows/check.yml) runs `tools/check-all.sh --since <base>`, so CI is diff-only too.
Non-style gates in check-all.sh do run whole-corpus on every change: structure, enforcers, index, schema tests and similar. Non-markdown files are never style-gated.

### OBSERVATIONS
1. Live forked enforcer on S13. tools/s13-plain-ascii.sh flags only `[\x{80}-\x{24FF}\x{2580}-\x{10FFFF}]`, so it allows Box Drawing U+2500-257F, which is S13's granted exception. tools/check-standing-context.sh, under "plain ASCII (S13)", flags all `[^\x00-\x7F]`, so it rejects box drawing. The two tools disagree at exactly the edge S0 warns about. The s13 header's claim that "the checker and the converter cannot disagree" holds only inside that one file. check-enforcers.sh cannot catch this because it scans only `tools/s<N>-*`.
2. style/README.md (S0) has no `Purpose` or `Territory` heading, but entities/E4-charter.md requires both as fixed headings in every charter. The charter-shape check is suspended in check-all.sh (tracked as B17), so nothing catches this.
3. S0 lists "the corpus-wide sweep" as a Fault, but E4 says a charter's Faults should hold population faults only. A sweep is a fault of a change, not of the population of rules.
4. S0 scopes style as "Doc, commit, and naming conventions", but no style entry covers commits. Naming is covered by skill K27, not by a style entry.
5. Small mismatch: S0 says an enforced rule names "exactly one tool". check-enforcers.sh checks only that the named tool exists and is executable, plus the orphan-tool check. It does not check that a rule names only one tool or that only one tool holds the rule.
