### s0.Q1
The corpus names this as a fault: style/README.md, Faults, "The forked enforcer. Two tools holding one rule, disagreeing at the edges. This is why a rule names exactly one."
The Enforcement boundary section says "An enforced rule names exactly one tool", and "One rule, one tool, and that tool owns both the check and the fix, so a rule cannot be reported by one implementation and refused by another."
The pairing is checked by tools/check-enforcers.sh "in both directions: a rule naming a tool that does not exist fails, and so does a per-rule tool no rule claims."
So the fix is to collapse to the single tool named in the rule's `enforced-by` frontmatter and retire the other.
NOT SETTLED: the corpus does not say which of the two tools should survive if neither is yet the declared one.
GUESS: keep the one named in `enforced-by` (or name one there), and port any edge cases worth keeping into it.

### s0.Q3
No, not by default. style/README.md: "Style is gated on changed files rather than on the whole corpus. The corpus carries debt that predates the checkers, so gating the diff blocks new debt and converts the rest as sections are edited."
tools/check-all.sh confirms it: "s6 s8 s10 s12 s13 s14 one sovereign checker per style rule, on changed files only"; by default it gates markdown changed against origin/main (committed, staged, unstaged and untracked).

### s0.Q7
style/README.md, Faults, lists the unhealthy shapes:
forked enforcers (two tools holding one rule, disagreeing at the edges);
orphaned rules (a convention nobody enforces and nobody reviews, "which teaches readers that the layer is decorative");
an unscoped medium (rules for a non-document medium scattered among the document rules with nothing grouping them);
work rules in style clothing (conventions that govern what the work does or records rather than how the artifact reads);
and the corpus-wide sweep (converting all legacy debt in one commit, an unreviewable diff hiding a real change).
"What earns an entry" implies another: rules that rest on aesthetic preference with no real defect behind them, or that apply inside only one document.
The Axiom alignment section notes a standing weakness: nine of fifteen are held only by reading, "so their hold is as strong as the review that reads for them".

### OBSERVATIONS
- tools/README.md (line ~63) says changed means "committed against the base plus staged plus unstaged", but tools/check-all.sh also includes untracked files (`git ls-files --others`); the README omits that.
- tools/check-all.sh has a duplicated, partly stale comment: "Committed against the base, plus staged, plus unstaged." appears once alone, then again with "plus untracked".
- S15 is listed as held by "reading", yet tools/check-guidance-placement.sh reads style/S15-message-to-a-human.md. That tool checks that tested guidance text landed verbatim, not the rule's conformance in other artifacts, so it is not an enforcer. Still, a reader could take it as one.
- style/README.md calls the gaps "Commit messages" and "Source code" new media. It does not say whether a source-code comment rule would be style or a skill such as K27, so Q5's placement is only partly settled.
- tools/check-all.sh notes that check-charter-shape.sh is suspended (tracked as B17). This is not a style issue but is noted.
