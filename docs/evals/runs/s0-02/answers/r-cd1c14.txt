### layer-charters.H1
The rules layer (`rules/`, charter RU0).
methods/README.md (M0) uses this exact example: "The first question is about a system's properties, not about how universal a ban sounds: *credentials are never committed* binds an action in a situation, and is a rule."
Run through M0's placement order: it is not "a limit a system is built toward" (so not an axiom), it produces no result of its own (not a method), it does not govern an artifact's form (not style), and it "leave[s] a trace in the record of the work that a check could test" (question 4), so it is a rule.
RU0 agrees: a rule "governs how work is done, produces nothing of its own, and leaves a trace a check could test".
The trace here is the repository history, which a check can inspect for committed credentials.
On placement it would most naturally sit at the "treating the record" moment, but neither M0 nor RU0 says which moment it belongs to. GUESS: treating the record.
No existing RU entry covers it. I checked the RU0 index (RU1-RU4).

### layer-charters.H2
The practices layer (`practices/`, charter PC0), but only if it is admitted.
By M0's order: it is not an axiom, it produces no result of its own (re-reading yields no verdict, artifact or record), and it does not govern an artifact's form.
It also leaves no trace: nothing in the record afterwards shows whether the request was re-read. So it reaches question 5, "Otherwise a practice".
PC0: a practice "leaves no trace: nothing in the record afterwards shows whether it was followed".
It would sit at the *verifying* moment, which PC0 says "hold[s] no practice today".
Placement is not the same as admission. PC0 says "A practice earns its place only by evidence that following it produces measurably different work" and "A practice is not minted to fill a moment". Until that difference has been observed, it is "a proposal" ("The unevidenced practice" fault).
GUESS: if the re-read had to be recorded (for example a closeout field quoting the request), it would leave a trace and become a rule.

### layer-charters.H3
The methods layer (`methods/`, M0), because following it "produce[s] a result of its own - a verdict" (M0 placement question 2).
An entry already covers it: M1 "Triangulated review - minimum 4 independent inputs" (methods/M1-triangulated-review.md).
M1 says to "require **at least four genuinely independent inputs** before reaching a verdict", applied when "Reviewing patches or designs that ship to production or upstream".
Its rationale is that "the reconciliation is where real bugs surface", which matches "compare them".
M0 places M1 at the *verifying* moment and calls it the "one primitive" that "carries the set".
M0 says "Prefer strengthening an existing entry to adding a neighbour", so the guidance should go into M1 rather than become a new entry.

### layer-charters.H4
The style layer (`style/`, S0).
M0 placement question 3 asks: "Does it govern how an artifact is written - its form, whatever the work was?" Heading case is about form, so it is style.
S0: style is "Rules about the artifact itself, judged by reading the output rather than by watching it being produced".
M0's table: "the artifact you produce | style/ | the object is the text".
Admission is again a separate test. S0 says "A convention earns one when its absence has produced a real defect in a real artifact" and "Aesthetic preference does not qualify". Heading case would need such a defect shown.
S0 also says "Prefer a rule a script can hold". Sentence case can be stated as a predicate, so it should come with an `enforced-by` tool.
No existing S entry covers heading case. I checked the S0 index (S1-S15) and grepped for "sentence case".

### layer-charters.H5
A rule must declare `trace` in its frontmatter: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md, Member shape).
The schema confirms this. In schemas/catalog-entry/v1alpha1/catalog-entry.schema.json, `trace` is required when category is `rule` and the id matches `^RU[1-9][0-9]*$`, with `minLength` 20.
A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md).
Optionally, a rule may name an enforcer in `enforced-by` "when a tool checks it". `tools/check-enforcers.sh` holds that tool to existing.
A rule with no tool "is still a rule, and is checked by reading the trace" (RU0). The schema's `trace` description says naming a tool "is enforced-by's job, and is optional".

### layer-charters.H6
The order comes from M0 (methods/README.md, "Placement"). RU0 and PC0 cite it. Ask in order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? Then it is an axiom (`axioms/`).
2. Does following it produce a result of its own (a verdict, an artifact, a record)? Then it is a procedure (`methods/`). Guidance that only requires a record to carry something is a rule.
3. Does it govern how an artifact is written, its form whatever the work was? Then it is style (`style/`).
4. Does it leave a trace in the record of the work that a check could test? Then it is a rule (`rules/`).
5. Otherwise it is a practice (`practices/`).
RU0 summarises the order as "axiom, procedure, style, rule, practice".

### layer-charters.H7
Strictly, every one of M0's six moments holds at least one entry, so no whole moment is empty.
Entering has M8 and PC1. Committing to a design has M7. Verifying has M1 and M2. Deciding what to keep has RU1 and RU3. Treating the record has M9, RU2 and RU4. Handing over has M10.
The gap the corpus records is inside *handing over*: handing work in progress to another agent or a later session.
M0 says: "handing work in progress to another agent or a later session has no procedure at all". M10 covers only handing understanding and decisions to a human.
RU0 lists handing over among the moments that "hold no rule today", and notes that "A rule for handing over - *a handover record names what is unfinished* - would leave a trace, and none exists".
PC0 lists handing over among the moments that "hold no practice today".
So agent-to-agent or session-to-session handover is the one point with no procedure, no rule and no practice.

### OBSERVATIONS
- practices/README.md (PC0) says "*Verifying*, *deciding what to keep* and *handing over* hold no practice today". Its own territory table shows a practice only at Entering (PC1), so committing to a design and treating the record also hold none. The gap list is incomplete.
- methods/README.md says "procedures sit at five of the six" moments but never names the empty one. Its table shows it is "deciding what to keep", which is covered by rules RU1/RU3.
- H7's wording ("nothing at all governing it") does not fit any whole moment. Only a sub-case of handing over (agent or session handover) is empty across all three layers.
- M1 is titled "minimum 4 independent inputs" but its rationale says "sometimes 3 is enough", which weakens the floor its title states.
- M1 and PC1 use a "## Rule" body heading even though they are a method and a practice. That blurs the rule/method/practice terms M0 defines.
- The catalog-entry schema does not forbid `trace` on a practice. The rule "if it acquires one, it is a rule and moves" is enforced only by the charter text, not by the schema.
- M0's "What belongs here" table heads its first column "If the rule governs", using "rule" loosely for any guidance.
