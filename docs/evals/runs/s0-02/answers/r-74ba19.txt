### s0.Q1
The corpus names this as a fault and rules it out by design. style/README.md, Faults: "The forked enforcer. Two tools holding one rule, disagreeing at the edges. This is why a rule names exactly one."
Enforcement boundary: "An enforced rule names exactly one tool ... One rule, one tool, and that tool owns both the check and the fix, so a rule cannot be reported by one implementation and refused by another."
The pairing is declared in each rule's `enforced-by` frontmatter, and tools/check-enforcers.sh checks it in both directions: a rule naming a tool that does not exist fails, and so does a per-rule tool that no rule claims (tools/README.md, check-enforcers.sh).
So the fix is to fold the check into the single tool the rule names and remove the second one.
GUESS: if the second tool were a per-rule `sN-*` script that no rule claims, check-enforcers.sh would flag it as an orphan. A second tool with any other name might not be caught.

### s0.Q3
No, not by default. style/README.md, Enforcement boundary: "Style is gated on changed files rather than on the whole corpus. The corpus carries debt that predates the checkers, so gating the diff blocks new debt and converts the rest as sections are edited."
tools/README.md (check-all.sh) agrees. `tools/check-all.sh` checks files changed against origin/main, and "changed" means committed plus staged plus unstaged. `--all` checks the whole corpus, and `--since REF` changes the base.
CI calls `tools/check-all.sh --since <base>` (.github/workflows/check.yml), so CI is also diff-scoped.
Only the style checks are diff-scoped. Other gates in check-all.sh, such as entry contracts and the tests, run whatever changed (tools/check-all.sh comments).

### s0.Q7
style/README.md, Faults, lists five unhealthy shapes:
(1) The forked enforcer: two tools hold one rule and disagree at the edges.
(2) The orphaned rule: nobody enforces it and nobody reviews it, which "teaches readers that the layer is decorative".
(3) The unscoped medium: rules for a non-document medium scattered among the document rules, with nothing grouping them.
(4) The work rule in style clothing: a rule about what the work does or records, filed where authors applying rules will not look.
(5) The corpus-wide sweep: all legacy debt converted in one commit that nobody can review.
"What earns an entry" adds another: entries based on aesthetic preference rather than a real defect. Axiom alignment notes a current weakness: nine of fifteen rules are held only by reading, so they are only as strong as the review.
