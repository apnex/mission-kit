### layer-charters.H1
It belongs in `rules/`. The corpus states this directly in methods/README.md (M0), Placement: "*credentials are never committed* binds an action in a situation, and is a rule."
M0 also explains why the first placement question does not make it an axiom: "The first question is about a system's properties, not about how universal a ban sounds".
It produces no result of its own (question 2) and does not govern an artifact's form (question 3). It does leave a trace a check could test (question 4): the repository's history shows whether a credential was committed. rules/README.md (RU0) defines a rule as one that "leaves a trace a check could test".
No existing entry covers it: RU1-RU4 deal with yield, frozen history, deferral and publishing rewritten history.
A new entry would have to declare a `trace` in frontmatter (RU0 "Member shape"; the catalog-entry schema requires `trace` for category `rule`).
GUESS: it would sit at the "treating the record" moment, but the corpus does not place this proposal in a moment, so that is NOT SETTLED.

### layer-charters.H2
Going by M0's placement order, it is a practice, in `practices/`. It is not a limit a system is built toward (Q1). Re-reading produces no verdict, artifact or record (Q2). It does not govern an artifact's form (Q3). And nothing in the record afterwards shows whether the re-read happened (Q4 fails).
practices/README.md (PC0): a practice "leaves no trace: nothing in the record afterwards shows whether it was followed".
PC0 also separates placement from admission: "placement says guidance *is* a practice; admission says whether it has earned an entry, which takes observed evidence". It earns an entry only with "evidence that following it produces measurably different work".
GUESS: it falls at the "verifying" moment, which PC0 lists as holding no practice today ("*Verifying*, *deciding what to keep* and *handing over* hold no practice today").
If it were changed so that the re-read must be recorded (for example, a done-note that quotes the request), it would leave a trace and become a rule (PC0: "if it acquires one, it is a rule and moves").

### layer-charters.H3
It belongs in `methods/`, because following it produces a result of its own, a verdict (M0, Placement Q2: "Does following it produce a result of its own - a verdict, an artifact, a record? A procedure, here.").
An entry already covers it: M1, methods/M1-triangulated-review.md, "Triangulated review - minimum 4 independent inputs". Its hydrate-when is "You are reviewing a patch or design that ships to production or upstream".
M1 says: "require **at least four genuinely independent inputs** before reaching a verdict". It names the canonical four for a patch (upstream baseline, prior-version intent + review, archaeology, community signal). It also says "The reconciliation is where real bugs surface", which matches the "compare them" step.
M0 places M1 at the "Verifying" moment and calls it the primitive that "carries the set".
So M1 should be strengthened, not duplicated (M0: "Prefer strengthening an existing entry to adding a neighbour").

### layer-charters.H4
It belongs in `style/`, because it governs an artifact's form: how a heading is written, whatever work produced the document. That is M0 Placement Q3 ("Does it govern how an artifact is written - its form, whatever the work was? Style").
style/README.md (S0): "A **style rule** governs an artifact's form, and is judged by reading the output rather than by watching it being produced."
No current S-entry covers heading case. GUESS: it would fit the "Token" or "Section" grain row; the corpus does not say which.
To earn an entry it must meet all three of S0's conditions. It governs form. "Its absence produced a real defect in a real artifact ... Aesthetic preference does not qualify". And it holds across artifacts. Sentence case may fail the second unless a real defect is shown.
S0 also says "Prefer a rule a script can hold". Heading case can probably be stated as a predicate over text, so it should name a single `enforced-by` tool (GUESS that a checker is feasible).

### layer-charters.H5
A rule must declare `trace` in frontmatter. rules/README.md (RU0), Member shape: "A rule declares its `trace` in frontmatter: the observable in the record that shows it was kept or broken, required by the catalogue contract." The schema enforces this (catalog-entry.schema.json: if category is `rule` and the id matches `^RU[1-9][0-9]*$`, then `trace` is required, with minLength 20).
A practice declares no `trace` (PC0: "It declares no `trace`; if it acquires one, it is a rule and moves").
Optionally, a rule may name `enforced-by`, the tool that checks it, which must match the pattern `^tools/`. RU0 says "It names an enforcer in `enforced-by` when a tool checks it ... a rule with no tool yet is still a rule". The schema's `trace` description says naming a tool "is enforced-by's job, and is optional".

### layer-charters.H6
From methods/README.md (M0), Placement ("Ask in order, and stop at the first yes"):
1. Is it a limit a system is built toward, in force for every system with the traits it names? Then it is an axiom (`axioms/`).
2. Does following it produce a result of its own (a verdict, an artifact, a record)? Then it is a method/procedure (`methods/`). Merely requiring a record to carry a field or reason is not this, and is a rule.
3. Does it govern how an artifact is written, its form whatever the work was? Then it is style (`style/`).
4. Does it leave a trace in the record of the work that a check could test? Then it is a rule (`rules/`).
5. Otherwise it is a practice (`practices/`).
RU0 and PC0 cite this same order ("axiom, procedure, style, rule, practice, asked in that order").

### layer-charters.H7
The gap is handing over work in progress to another agent or to a later session, at the "handing over" moment.
M0: "handing work in progress to another agent or a later session has no procedure at all". It adds that this applies "to an agent working alone as much as to many: a lone agent hands over to its own next session".
RU0: "*handing over* ... hold[s] no rule today", and "A rule for handing over - *a handover record names what is unfinished* - would leave a trace, and none exists."
PC0: "*handing over* hold[s] no practice today."
Strictly, the handing-over moment as a whole is not empty: M10 (guided dialogue) governs handing understanding and decisions to a human. What has nothing at all governing it is the agent/session handover sub-case.
M0 says it is "not a defect until something fails there", but it is "where to look first when something does".

### OBSERVATIONS
- PC0's "Gaps tested" lists only verifying, deciding what to keep and handing over as holding no practice. But its territory table holds only Entering (PC1), so committing to a design and treating the record also hold no practice and go unmentioned.
- No moment of the six is wholly empty across methods, rules and practices. Entering has M8 and PC1, committing to a design has M7, verifying has M1 and M2, deciding what to keep has RU1 and RU3, treating the record has M9, RU2 and RU4, and handing over has M10. H7's "nothing at all" therefore applies only to the agent/session handover sub-case.
- rules/README.md and practices/README.md say members "came from `methodology/`", but the directory is `methods/`. This is probably a stale name.
- methods/README.md, end of "How the procedures compose": a `---` line follows a text line directly with no blank line between them. In CommonMark that turns the preceding line into a setext H2 heading, not a horizontal rule.
- M1 is a method but its body section is headed "## Rule". It also states a "minimum 4" floor while saying "sometimes 3 is enough" and "below 3 the failure mode is predictable", so the floor is stated two ways.
- rules/README.md has no "What earns an entry" or admission section. methods, practices and style each have one.
