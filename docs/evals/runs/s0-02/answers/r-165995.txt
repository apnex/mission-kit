### system-boundary.S1
Only the launcher's axioms bind: the floor set A3, A4, A8, A9, A14 (axioms/README.md matrix, row `any-system`; each file's `applies-to: [any-system]`).
The launcher has no traits: it holds no state (T1), one operator watches it, so a human is in the loop (T4), "one actor using several tools is not multi-agent" (T3), and there is no model (T5). E5 says "A one-shot script with no traits is a system, bound by the axioms every system carries".
The service is not altered: A0 says "A system it only composes with, through a contract the change leaves as it was, is not altered, and its axioms do not bind", and E5 gives "A launcher that hands sessions to a service through a declared interface composes with it" as its example of compose.
"Nothing crosses ... except a declared session interface" reads as declared and honoured, which E5 requires for the separation to hold ("Declared against honoured").
Separately, E5 says the organisation's axioms govern how the change is made and recorded, but they are not one of the systems the change alters.

### system-boundary.S2
Both systems' axioms bind: A1, A3, A4, A5, A6, A7, A8, A9, A10, A13, A14 - every axiom except A2, A11 and A12.
A0: a change answers to "any system whose contract with it the change alters". E5: "changing an unversioned interface alters every consumer at once, so the change answers to all of them immediately."
The service is stateful (T1 -> A1). Its agents hand work to one another, so it is multi-agent (T3 -> A5, A6, A7, A10, A13). No human is in the synchronous loop, so it is autonomous (T4 -> A7, A10, A13). It is not declarative (no A2) and has no model (no A11, A12). The launcher adds only the floor (A3, A4, A8, A9, A14).
E5 also says adding versioning to the interface "is encouraged, not required; if it is not done, the gap is recorded" - so if you do not version it, record the gap.

### system-boundary.S3
The service's full set binds: A1, A3, A4, A5, A6, A7, A8, A9, A10, A13, A14 (no A2, A11, A12).
E5 "Contain": "A module inside a service is a system, and the service contains it, whether or not the module's interfaces are declared." E5 also says "changing a module changes the service it sits in".
A0: a change answers to "the system it modifies, every system containing it".
The module having no state on its own does not matter. E5 says the service "has every trait any part it contains has", and its "Why precision matters" section warns against a stateful system escaping its axioms "by being described as stateless modules".
The module itself, as a system with no traits, contributes only the floor, which is already in the set.

### system-boundary.S4
Only the library's axioms bind: the floor set A3, A4, A8, A9, A14 (no state and no model; the corpus also gives no sign of multiple actors or unattended operation).
The interface and its behaviour are unchanged, so no consumer's contract is altered (A0). E5: "Publishing a new version of an interface alters no consumer that has not adopted it; each adoption is a change to that consumer, and answers to that consumer's axioms; the component is not altered by being adopted."
E5 "Why precision matters" rejects the opposite reading explicitly: otherwise "a small shared library would carry the axioms of every system that uses it".
One exception from E5: "A declared version range - any 2.x - is adoption in advance: a release within it alters every consumer bound by the range". The question says each consumer adopts as a separate change, so I take it that no ranges are in play.
If any consumer did bind a range that covers the release, that consumer's axioms would bind too. E5 also assumes each consumer honours the interface; one that reaches into the internals stays one system with the library.

### system-boundary.S5
With no declared boundary and the service depending on the log lines, the two are "one system, with the traits of both" (E5 Boundaries; A0 "the axioms either unit would bring all bind").
So the change answers to A1, A3, A4, A5, A6, A7, A8, A9, A10, A13, A14 (stateful + multi-agent + autonomous + floor; no A2, A11, A12).
Also wrong: the undeclared dependency "is itself a fault against A3", which requires units to interact only through declared contracts (E5; A0; A3 Air-Gap Principle). The log line is "a contract in fact, not a declared boundary - and a change to it reaches across" (E5).
E5 also makes it your job: "A change that alters what an undeclared neighbour reaches into owns that boundary: declaring and honouring the interface is inside its scope, not optional."
In practice the change will probably break the service's parsing, which A3 calls "Logic Leakage". The fact that no larger containing system is declared does not matter: E5 says this is "not a third way of relating" - the two are simply treated as one.

### system-boundary.S6
It is defined in entities/E5-system.md: "A system is a unit of engineering with a boundary: what is inside it, and the contracts through which anything outside reaches it."
The boundary separates it from a neighbour "only where it is declared and honoured"; otherwise the two "are one system for deciding what a change answers to".
Traits describe a system and axioms bind it. Systems relate in exactly two ways, contain and compose.
E5 Boundaries says a system is not by definition a repository, a deployment unit or a process, and is not defined by size or by traits. E5 also says the organisation doing the work is itself a system.
E6 adds that a component is "a system seen as a part of a larger system that contains it".

### OBSERVATIONS
- Possible tension in S2: A3's Semantic Bit-Masking says interfaces are "explicit, versioned contracts", so an unversioned interface is a gap A3 names. A0 says "work that touches a gap closes as much of it as the touch allows", where the touch is "the part the change already alters" - and S2 alters exactly that interface. E5, however, says versioning it is "encouraged, not required". E5 says it governs here, but A0 alone would suggest versioning is required. NOT SETTLED which reading wins beyond E5's explicit statement.
- E5 itself hedges whether a bypass of an interface counts. The S1 answer depends on "honoured", which I inferred from "nothing crosses except" rather than from an explicit statement.
