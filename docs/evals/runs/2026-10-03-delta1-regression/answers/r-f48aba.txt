### boundary-bypass.B1
Yes. Your change answers to O's axioms, as well as to T's and to those of the service that contains T.
E5 (Discriminators, "Declared against honoured") says: "A unit that reaches past it - calling internals ... - stays one system with it".
A0 ("What brings an axiom into force") says that where a boundary is "one written and reached past ... the two are one system with the traits of both, and the axioms either unit would bring all bind".
E6's blast-radius row agrees: a change reaches "any unit that reaches it ... with no declared interface". So T's unchanged interface and behaviour do not keep O out.
On the bypass itself, A3 (Mechanics, "Bypass as Signal") calls it "a fault in the consumer and a signal about the interface". A detected bypass "triggers an evaluation of the interface against the component's duty and its vision". That evaluation ends with O moved onto the interface or the interface adjusted.
A3's Air-Gap Principle also forbids the bypass: "no unit reaches into another's internals".

### boundary-bypass.B2
It answers to O and not to P. It also answers to T and to the service that contains T (A0: "every system containing it").
E5 says the separation is per pair: "a neighbour that uses the interface composes with the unit, while one that bypasses it does not."
A0 says a system the change "only composes with, through a contract the change leaves as it was, is not altered, and its axioms do not bind". That is P.
O reached past the declared interface, so O is one system with T, and O's axioms bind (A0, E5, and A3 "Bypass as Signal": "Until then the two remain one system").
P is inside the same service, so the service's axioms bind the change anyway. P's own axioms as a separate system do not.

### boundary-bypass.B3
No. For the T-O pair nothing has changed, and they are still one system for deciding what a change answers to.
E5 says: "declaring an interface and leaving the bypass in place separates nothing."
E6 (Definition) says the boundary "separates the component from a neighbour only where they are declared and that neighbour uses them", and "Declaring its interfaces, and its neighbours using them, is what separates it."
E5 (Boundaries): "Declaring the boundary, and moving the dependency onto it, is what makes them two again." In this case the dependency was not moved.
The new interface does separate T from any neighbour that uses it (E5: "The separation is per pair").

### boundary-bypass.B4
Treat each bypass as a fault in that consumer and as a signal about T's interface (A3 Mechanics, "Bypass as Signal"). Then evaluate T's interface against T's duty and its vision.
The evaluation must end with each consumer moved onto the interface, or with the interface adjusted (A3). A3 Success signal 5 adds that each detected violation "is evaluated against the component's duty rather than only corrected in the consumer".
Until that is resolved, each bypassing component stays one system with T for binding (A3, A0, E5). So any change to T's internals answers to all of their axioms.
If you adjust the interface, that change answers to every consumer whose contract it alters, or, for a versioned interface, to each consumer that adopts it (A0, E5).
If the work is outside your change's scope, A0 says to record it with its evidence and a revival trigger (RU3) instead of passing it silently.
NOT SETTLED: whether several bypasses count for more than one. GUESS: several consumers bypassing the same interface is a stronger sign that the interface falls short of T's duty.
NOT SETTLED: who must run the evaluation, and whether it falls inside the scope of the change that found the bypasses.

### OBSERVATIONS
- A3 asks you to evaluate the interface against "the component's duty and its vision". No entry I read defines a component's vision. AR6 Vision is scoped to a programme, and I did not open AR6 to check whether it reaches components.
- A3 says what a detected bypass triggers, but not who carries out the evaluation or whether the current change must do it. A0's scope/adjacency rule only partly answers this: a bypassing consumer reaches T with no declared interface, so it is not "adjacent" in E6's sense, which makes the opportunistic-improvement route unclear.
- Transitivity is not settled. If O is one system with T, and O is also one system with some other unit through a separate bypass, the text does not say whether that unit's axioms reach a change to T.
- A0 says a change touches "any consumer whose contract it alters". It is unclear whether changing internals that O depends on, while leaving T's behaviour unchanged, "alters" O's contract in fact (E5: "a contract in fact"). The one-system rule makes this moot for binding, but the two framings could be read differently.
