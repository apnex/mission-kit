### system-boundary.S1
Only the launcher's axioms: the floor A3, A4, A8, A9, A14.
A0 ("What brings an axiom into force"): "a change answers to every system it alters... A system it only composes with, through a contract the change leaves as it was, is not altered, and its axioms do not bind."
E5 Definition gives this exact case as composition: "A launcher that hands sessions to a service through a declared interface composes with it", and the boundary is honoured because nothing else crosses ("written down, and the only way the neighbour reaches it").
The launcher has no traits, and E5 Boundaries says "A one-shot script with no traits is a system, bound by the axioms every system carries."
Separately, the organisation's own axioms govern how the change is made and recorded, but E5 says those "are not one of the systems the change alters".

### system-boundary.S3

### system-boundary.S4
Only the library's axioms: the floor A3, A4, A8, A9, A14.
The ten consumers compose with the library through a declared, versioned contract that this change leaves unchanged, so A0 says they are "not altered, and [their] axioms do not bind".
E5: "A versioned contract changes only for the systems that adopt the new version... each adoption is a change to that consumer, and answers to that consumer's axioms; the component is not altered by being adopted."

Caveat: E5 says a declared version range "alters every consumer bound by the range" when a release falls inside it. The question says each consumer adopts separately, so I assume no range is in play.

### system-boundary.S6
It is defined in entities/E5-system.md: "A system is a unit of engineering with a boundary: what is inside it, and the contracts through which anything outside reaches it."
A boundary separates it from a neighbour "only where it is declared and honoured". Traits describe a system, and axioms bind it. Systems relate only by contain or compose.
E5 Boundaries says a system is "Not a repository, a deployment unit or a process by definition", and "Not defined by size or by traits".
E5 also says the organisation doing the work is itself a system. E6 defines a component as "a system seen as a part of a containing system".
