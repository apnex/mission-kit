If you make it, do it "as a change of its own" that answers to every system it alters (A0). NOT SETTLED: whether Y's error-message text is part of Y's declared interface. ### component.C2
It is defined in entities/E6-component.md: "A component is a system seen as a part of a larger system that contains it", with "one duty at the altitude where it appears as a part", and it "exposes and consumes interfaces"; its boundary is those interfaces where they are declared and used. It is not a different kind of thing: "Every component is a system; component names its place in a containing system". The difference is which question you are asking: "Traits, axioms and what a change answers to are questions about a system. Duty, interfaces, neighbours and blast radius are questions about a component" (E6 Discriminators). A system that nothing contains, such as a whole product seen from outside, "is not a component of anything" (E6). entities/E5-system.md defines system as "a unit of engineering with a boundary", and gives the relations contain and compose. E6 also says a component is not just a file, module, directory or SysML part, and does not need to be registered in components/ ("Most components are never registered").

### component.C3
No. E6 ("Boundary against directory"): "A component's directory addresses it ... Its boundary is its declared interfaces"; E5 also says "A directory ... is the boundary of neither the system nor the component". There is no declared interface, so parts/thing is still a component, but "nothing separates it yet: for deciding what a change answers to, it is one system with whatever reaches into it" (E6). E5 adds that the two are "one system, with the traits of both". What is wrong: "The undeclared dependency is itself a fault against A3" (E5; A3 Air-Gap Principle: "no unit reaches into another's internals"). The fix is "Declaring the boundary, and moving the dependency onto it" (E5). Per A3 "Bypass as Signal", the interface should first be evaluated against the component's duty, so it covers what parts/other legitimately needs. E5 also says a change that alters what the undeclared neighbour reaches into "owns that boundary: declaring and honouring the interface is inside its scope, not optional".

### component.C4
Your change answers to "the system it modifies, every system containing it, and any system whose contract with it the change alters" (axioms/README.md): that is P, the service, and anything that contains the service. Q is not altered: "A system it only composes with, through a contract the change leaves as it was, is not altered, and its axioms do not bind" (A0; E6 blast radius: an adjacent component is reached "only if the interface between them changes"). This holds only if Q honours P's interface. If Q reaches past it, E5 says they "stay one system". Q is a candidate for opportunistic improvement. It shares a declared interface with P, so it is adjacent (E6), and A0 includes a component "that stands on it". E6 notes that this direction gives "adjacency with less payback, not none", so Q must still pass A14's tangent test. If you improve Q, do it as a separate change that answers to Q's systems; otherwise record it with a revival trigger (A0, RU3).

### OBSERVATIONS
- A0 counts only what a change "newly depends on" as touched. So it is not stated whether a dependency that already existed (X already calling Y in C1) is touched, or only adjacent. I treated Y as adjacent.
- Neither A0 nor E5 says whether an error message's wording is part of a declared interface. This decides whether changing Y alters Y's consumers.
- A14's tangent discipline defines adjacency in one direction only ("infrastructure the main line will stand on"). A0 includes both directions ("one it stands on, or one that stands on it"). E6 reconciles this with "the other direction is adjacency with less payback, not none", but A14 read alone suggests that Q in C4 does not qualify.
- A3 "Bypass as Signal" is worded for reaching past a *declared* interface. C3 has no declared interface, so the case is covered by A3's Air-Gap Principle and E5, not by Bypass as Signal directly.
