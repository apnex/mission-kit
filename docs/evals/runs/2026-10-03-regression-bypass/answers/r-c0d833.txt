### axiom-direction.Q1
The service is stateful, so A1 binds it (traits/T1-stateful.md; axioms/A1), and a component holding important state only in process memory is an A1 gap: the mandate says "No functional unit possesses private, opaque, or transient truth", and the fault "Hidden State Problem - state lives inside a process; other actors reason about a different reality" fits exactly (A5's "Architect Amnesia" is also relevant, as the service is multi-agent).
A0 ties what you owe to scope: "A change touches what it modifies, what it newly depends on, and any consumer whose contract it alters"; inside scope you must close "as much of it as the touch allows".
If your feature newly depends on that component, its gaps "must not be built on" (A0) - so do not read or build on that hidden state as if it were shared truth.
If the component is untouched, "improvement is considered, never mandated": if it is adjacent (shares a declared interface) you may close it opportunistically as a separate change under A14 tangent discipline; otherwise record it with evidence and a revival trigger (M5), since what work happens next is the director's call (R4, AR3).
"Either way the gap is recorded. Passing it silently is what the axiom forbids" (axioms/README.md).
For your own feature, "new work never repeats a gap the axiom names": keep its state in the shared, durable, queryable backplane, not in process memory (A1 Mechanics, Success signal 2).

### axiom-direction.Q2
An axiom is a direction to build toward, not a test to pass: A0 calls it "a load-bearing asymptote - a limit a system is built toward", and "a system is not wrong for being short of it; it is wrong for moving away from it" (axioms/README.md).
So when I change a bound system, the axiom tells me two things at once: "No change may move the system away from the limit, and each change moves it toward the limit as far as the change's own scope allows."
Inside my change's scope I must not repeat a gap it names and should close what I touch; outside that scope I consider the gap and either close it opportunistically or record it, never pass it silently.
A0 carries a correction banner rejecting the pass/fail reading ("The conformance reading" fault), because read that way nearly every system fails and the rule "gives no direction".
A gate checks only the binary part of this: that the change moved the system no further from any limit in force.
All axioms in force bind together and none may be traded against another ("orthogonal in statement and conjunctive in force").
