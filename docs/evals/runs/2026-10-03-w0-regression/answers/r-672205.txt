### composition.P1
Method: apply each trait test to the system, then take the union of axioms those traits bring into force plus the floor (traits/README.md "Traits bind by union ... a system's obligations are the union of every axiom any of its traits brings into force, plus every axiom on the floor"; axioms/README.md "in force ... if, and only if, that system's architecture satisfies at least one of the axiom's applies-to tags").
Traits: stateful (T1 test: writes and reads back authoritative state), multi-agent (T3: work crosses between independent actors), llm-in-the-loop (T5).
Floor (any-system): A3, A4, A8, A9, A14; stateful: A1; multi-agent: A5, A6, A7, A10, A13; llm-in-the-loop: A5, A11, A12 (applicability matrix in axioms/README.md, cross-checked against each axiom's own `applies-to` frontmatter and the T1/T3/T5 "Axioms it brings into force" sections, which agree).
Result: A1, A3, A4, A5, A6, A7, A8, A9, A10, A11, A12, A13, A14 - thirteen axioms.
Autonomous (T4) is not stated, but would add nothing: its axioms A7, A10, A13 are already in force via multi-agent.
A2 (declarative) is NOT SETTLED: the question does not say whether the service reconciles toward a declared spec (T2 test); if it does, all fourteen bind.
Separately, the organisation doing the work is itself a system whose axioms govern how the work is done and recorded (entities/E5-system.md; work-types/README.md assembly step 1).

Traits: not stateful (T1 "Not stateful: a pure function"), not multi-agent (T3 "a single agent working alone"), not llm-in-the-loop, not declarative (T2 "Not declarative: a script run once"); GUESS: not autonomous either, since one person runs it interactively (T4), and even if it were, A7/A10/A13 would be added.

A1 does not constrain the formatter's codebase: A1's `applies-to` is [stateful], and axioms/README.md says "`applies-to` answers *whether* an axiom binds, and it is the only field that does" and "a domain entry cites the axioms it must satisfy" - D1's citation says what A1 demands on that surface where it binds, not whether it binds.

### OBSERVATIONS
- The traits' "Axioms it brings into force" sections are hand-written inverse copies of axiom `applies-to` - the same "doubly-declared pairing" fault W0/D0 fixed for domains by generation - and tools/check-traits.mjs only checks the tag vocabulary, not these lists, so nothing stops drift.
- W8's Evidence section says if the roster collapses attester and executor "the seed fails or downgrades to `kind:review`", which can be read as permitting a same-agent review; W0 constraints 2 and 9 say a same-agent review never stands in.
- W7 is titled and defined as shipping a release artifact to an estate/channel, and its evidence contract (release artifact + deploy log, version/digest/SHA + rollback anchor) does not mention D7's evidence (records before/after, row counts, integrity checks), though W7 lists product-data as eligible.
- R3's engagement-mode lists code-owner-approve, but W13's evidenceAuthority is verifier-attestation with roleEligibility [architect, verifier, engineer] - consistent, but R3's list omits W22 axiom-alignment-gate, which is verifier-only.
- P1's "long-running service" leaves autonomy and declarativeness unstated; only declarativeness changes the answer (A2).
- INDEX.md tells readers to fetch from GitHub when no local checkout exists; I used only the provided corpus.
