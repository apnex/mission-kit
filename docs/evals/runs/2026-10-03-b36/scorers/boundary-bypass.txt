PROBE boundary-bypass.B4

Question:
A check detects that several components bypass T's declared interface to reach T's internals. What does the corpus ask you to do?

Key:
Treat the bypass as a signal, not only as faults in the consumers: evaluate T's interface against T's duty and vision. Either the consumers are wrong and are rerouted onto the interface, or the interface falls short of T's duty - the consumers have an unsignalled change request - and the interface is adjusted. An adjusted interface alters its consumers, so their axioms bind that change.

Rubric:
2 for the interface evaluation against duty and vision with both outcomes. 1 for only 'fix the consumers' grounded in A3, or only 'adjust the interface'. 0 for no action, or for forking or replacing T. Splitting T because the evaluation finds a second duty counts as adjusting the interface.

--- answer a-0658fcf7 ---
A3 Bypass as Signal treats each bypass as "a fault in the consumer and a signal about the interface: it may mean the interface falls short of the component's duty". It asks for "an evaluation of the interface against the component's duty and its vision", ending in each consumer "being moved onto the interface or the interface being adjusted". A3 Success signal 5 says each detected violation is "evaluated against the component's duty rather than only corrected in the consumer". So you should not only patch the consumers. Until this is resolved, each bypassing component stays one system with T for what a change answers to (A3; E5; A0). If the work falls outside the current change's scope, A0 says to record it "with its evidence and a revival trigger (RU3)" and not close it there. Larger choices of what work comes next belong to the director (R4, AR3). NOT SETTLED: whether several bypassers change the procedure. GUESS: several consumers bypassing T is stronger evidence that the interface falls short of T's duty, so adjusting the interface becomes more likely.
