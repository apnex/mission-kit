### charter-claims.V1
No, it should not narrow. `entities/E4-charter.md` says the vision "is what the set is for and what it claims to cover; the population is measured against it ... and it is never cut to fit what the set holds today", and "A claim no member yet fills is a gap ... naming it is how gaps are found".
It also says a territory's "extent is set by purpose, not by what it holds: a cell no member fills is kept and named as a gap, and removing it to match the population erases the gap it exposes."
And no, stating the scope is not all a charter does. E4 says "The rest of the charter is management": the territory shows where the population stands against the claim, the boundaries decide what enters and where the rest goes, the faults say how the set goes wrong, and changes go through *Changing a charter*.
The required concerns are Purpose, Territory, Boundaries, Composition, Faults and Index. Conditional concerns (Kinds, Member shape, Placement, Enforcement boundary, Sub-sets, Axiom alignment, Probes) apply when the property is present (E4 tables; see also `entities/E3-set.md`, "A set states what a member cannot").

### charter-claims.V6
No, not by itself. `domains/README.md` (D0) says the set "claims every surface work's evidence can land on, however many that proves to be". It also says "**The set grows when the territory finds a gap.** This set is not complete and is not expected to be", and gives `product-data` (D7) as a domain that entered this way.
The charter sets conditions, though. The new domain must close a real surface with "its own evidence contract, not by stretching a neighbour". It must not be a mode-domain or an "indistinct pair" (Faults). It must sit in a part row, and if no part fits, "the part is added with the domain".
An eighth domain that breaks those conditions would contradict the charter. One that meets them would not.
Some counts would go stale and need updating: `work-types/README.md` says "DOMAINS (N=7)", and D0's Faults say "Five of the seven current members".

### OBSERVATIONS
- `artifacts/README.md` (AR0) opens by calling the types "each with a schema". `schemas/README.md` (SC0) says lifecycle documents have "no contract at all" and only "prose templates". `AR1` and `AR6` each say "No template ships with this entry". So AR0's "schema", SC0's "prose templates" and those two entries do not agree.
- `W3` is titled "retire-or-hard-cut", but W0 says retiring a corpus entry is `W1`, and W3 is only for deleting a whole surface. The title could send a reader to the wrong work-type.
- RU0 and PC0 say their members "came from `methodology/`". The directory is `methods/`, and M0 says the entries moved from "here". This is either a stale directory name or an older name that is not explained.
- `E3` and `E4` both refer to "Thirteen charters". INDEX.md lists sixteen `<prefix>0` charters (A, R, D, W, M, RU, PC, ST, S, P, K, E, C, AR, T, SC). The figure is probably historical, but neither entry says so.
- W0 gives fixed counts ("DOMAINS (N=7)", "K~=26"). D0 says the domain set "is not complete and is not expected to be", so these counts will go stale when it grows.
- M0's Territory lists only `M8` at Entering. PC0 also places `PC1` at Entering ("how to begin in an unfamiliar collection"). PC1's own trigger is "about to add an entry to a curated collection", so it is not obvious that it is an "entering" practice.
