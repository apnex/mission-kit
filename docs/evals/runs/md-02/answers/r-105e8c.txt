### OBSERVATIONS
- `artifacts/README.md` opens by saying the document types are "each with a schema", but `schemas/README.md` says lifecycle documents have no contract and the artifact types carry only prose templates. The two disagree. AR0's test 5 ("Contracts in `schemas/` already own some shapes") also implies some lifecycle shapes are governed, but SC0 lists none.
- `work-types/W3-retire-or-hard-cut.md` defines its scope as deleting a surface "from the codebase", but its `domainEligibility` covers all seven domains, including knowledge-methodology. W0 also says retiring a corpus entry is `W1`, not W3, despite W3's title "retire-or-hard-cut". A reader routing by title would likely pick the wrong entry.
- `work-types/README.md` hard-codes axis counts ("M=4", "N=7", "K~=26"). These go stale when the domain or work-type sets grow, which D0 and W0 both expect.
- `entities/E3-set.md` and `entities/E4-charter.md` both say "Thirteen charters". INDEX.md now lists 16 `<prefix>0` charters (A0, R0, D0, W0, M0, RU0, PC0, ST0, S0, P0, K0, E0, C0, AR0, T0, SC0). The count may be historical, but it is not marked as such.
- ST0's candidate set for independent verification includes `A8`, an axiom. ST1 says axioms are "Cited, not enrolled: an axiom is a standing commitment, not a situated move". So the candidate list conflicts with how the only existing set treats axioms.
- PC0 puts `PC1` under Entering ("how to begin in an unfamiliar collection"), but PC1's trigger is "You are about to add an entry to a curated collection". That is arguably an authoring moment, not entering.
- `W1` build-a-slice `domainEligibility` leaves out `product-data`, while `W2` and `W3` include it. This may be intentional, but no file I read explains it.
- INDEX.md says to resolve links against a checkout or the raw GitHub URL. I used the local corpus only, as instructed.
