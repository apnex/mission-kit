### s0.Q1
The corpus names this as a fault: style/README.md, Faults: "The forked enforcer. Two tools holding one rule, disagreeing at the edges. This is why a rule names exactly one."
The remedy is stated under "Enforcement boundary": "An enforced rule names exactly one tool ... One rule, one tool, and that tool owns both the check and the fix, so a rule cannot be reported by one implementation and refused by another."
The pairing is declared in the rule's `enforced-by` frontmatter and verified in both directions by `tools/check-enforcers.sh` (a rule naming a missing tool fails, and so does a per-rule tool no rule claims); tools/README.md repeats this.
So the answer is to collapse to one tool, the one named in the rule's `enforced-by`, and remove or fold the other.
NOT SETTLED: the corpus does not say which of the two tools should survive, or how the edge-case disagreement is resolved on the merits.
GUESS: keep the tool the rule's `enforced-by` names, and settle the edge cases against the rule text, since S13's checker comment says the rule "has one definition".

### s0.Q2
No.
style/README.md, "What earns an entry", needs all three criteria, and criterion 2 is "Its absence produced a real defect in a real artifact, and a reader can be shown the difference. Aesthetic preference does not qualify."
A heading-capitalisation preference meets criterion 1 (it governs form) but fails criterion 2 unless someone can point to a real defect it caused.
The charter's Purpose also frames style as "a functional requirement rather than a preference".
If a real defect could be shown, it would also need to hold across artifacts (criterion 3), and the charter says to prefer stating it as a predicate with a tool ("Prefer a rule a script can hold").

### s0.Q3
Not by default.
style/README.md, "Enforcement boundary": "Style is gated on changed files rather than on the whole corpus. The corpus carries debt that predates the checkers, so gating the diff blocks new debt and converts the rest opportunistically."
`tools/check-all.sh` by default runs style only over markdown changed against `origin/main` (committed, staged, unstaged and untracked); CI passes `--since <base>` (.github/workflows/check.yml).
A whole-corpus run exists as a manual option, `tools/check-all.sh --all`, but the gate does not use it.
Also, only the six tool-held rules are checked by script at all; the other nine are reviewed by reading.
The non-style gates in check-all.sh (index, structure, schemas and so on) do run on every change, but that is not the style gate.

### s0.Q7
style/README.md, Faults, lists the unhealthy shapes:
the forked enforcer (two tools holding one rule and disagreeing at the edges);
the orphaned rule (a convention nobody enforces and nobody reviews, which teaches readers the layer is decorative);
the unscoped medium (rules for a non-document medium scattered among document rules with no sub-set grouping them once there are two);
the work rule in style clothing (a convention that governs what the work does or records filed as style);
the corpus-wide sweep (converting all legacy debt in one commit, giving an unreviewable diff that hides a real change).
By implication from "What earns an entry", rules admitted on aesthetic preference, or that hold only inside one document, would also be unhealthy.
The Axiom alignment section names current shortfalls in the same direction: nine of fifteen rules held only by reading, and three claimed media with no rule.

### OBSERVATIONS
- tools/README.md (check-all.sh section) says "Five checkers existed and nothing ran any of them, which is the unread-checker fault the charter names", but the style charter's Faults list has no "unread-checker" fault; the nearest is "The orphaned rule". It is unclear which charter is meant.
- tools/README.md says style "Changed means committed against the base plus staged plus unstaged", but tools/check-all.sh also includes untracked files (`git ls-files --others`). The doc is out of date with the script.
- tools/check-all.sh has a duplicated, superseded comment line ("Committed against the base, plus staged, plus unstaged.") just before the fuller version.
- tools/README.md describes check-charter-shape.sh as advisory with a flip to blocking tracked as `B4`, while check-all.sh says it is SUSPENDED pending a rebuild against E4, tracked as `B17`. The two disagree on status and tracking id.
- Some of "the remaining rules need judgement" while two tool-held rules (S8, S14) also "need judgement" for their fix. That is consistent (check vs fix) but easy to misread as contradictory.
- tools/check-enforcers.sh says conduct rules (`rules/RU*.md`) may also name an enforcer, but the orphan direction only looks under `style/`, so "one rule, one tool" is only checked in both directions for style rules.
