### s0.Q7
The *Faults* list in `style/README.md` describes it:
- Forked enforcers: two tools holding one rule and disagreeing at the edges.
- Orphaned rules: "A convention nobody enforces and nobody reviews, which teaches readers that the layer is decorative."
- Unscoped media: rules for a non-document medium scattered among the document rules with no sub-set grouping them.
- Work rules in style clothing: conventions about what the work does or records, filed where authors applying style will not look.
- Corpus-wide sweeps: one unreviewable commit that hides a real change.
From the entry criteria, it would also include rules that exist only because someone preferred them (fails criterion 2), or that apply inside a single document (fails criterion 3).
*Axiom alignment* names current weak points: nine of fifteen rules are held only by reading, and three claimed media (commit messages, code names, code comments) have no rule.

### OBSERVATIONS
- `style/README.md` links `tools/check-enforcers.sh`, and the index names six `tools/*` enforcers. `check.yml` calls `tools/check-all.sh`. There is no `tools/` directory in this corpus. That link is broken here, and I could not read any enforcement claim against the code that is supposed to enforce it.
- `INDEX.md` says "Run tools/generate-index.mjs", which is also missing from the corpus.
- The fork detection in `check-enforcers.sh` ("a per-rule tool no rule claims") seems to catch a second tool only if that tool counts as per-rule. A shared or general linter that also checks the rule could still fork it undetected. I inferred this and did not verify it.
- The "nine of fifteen" count in *Axiom alignment* is a hand-written number that repeats the generated *Held by* column. It matches now, but it can drift when a rule gains a tool.
- `INDEX.md` says links resolve against a local checkout, "otherwise fetch from" GitHub. That points outside the corpus I was restricted to, so I did not follow it.
