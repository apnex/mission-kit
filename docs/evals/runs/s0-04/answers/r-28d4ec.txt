### layer-charters.H5
A rule must declare `trace` in its frontmatter: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md, Member shape).
The schema enforces this. catalog-entry.schema.json requires `trace` when category is `rule` and id matches `^RU[1-9][0-9]*$`, with minLength 20.
A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md).
Optionally, a rule may name `enforced-by` (a path matching `^tools/`) "when a tool checks it". `tools/check-enforcers.sh` then holds that tool to existing. The schema's trace description says naming a tool "is enforced-by's job, and is optional".
"A rule with no tool yet is still a rule, and is checked by reading the trace" (RU0).

### layer-charters.H6
methods/README.md (M0) gives the order. Ask in order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? If yes, it is an axiom.
2. Does following it produce a result of its own (a verdict, an artifact, a record)? If yes, it is a method. Guidance that only requires a record to carry something is not a method; it is a rule.
3. Does it govern how an artifact is written (its form, whatever the work was)? If yes, it is style.
4. Does it leave a trace in the record of the work that a check could test? If yes, it is a rule.
5. Otherwise, it is a practice.
RU0, PC0 and S0 each cite this as the single statement of placement ("axiom, procedure, style, rule, practice, asked in that order").

### layer-charters.H7
The gap is handing over work in progress to another agent or to a later session.
M0: "handing work in progress to another agent or a later session has no procedure at all". M10 covers handing understanding and decisions only to a human.
RU0: *handing over* holds no rule, and "A rule for handing over - *a handover record names what is unfinished* - would leave a trace, and none exists."

M0 adds that this applies to a lone agent too ("a lone agent hands over to its own next session"), and that it is "where to look first when something" fails.
At the level of the whole moment, *handing over* is not completely empty, because M10 is there. The completely ungoverned part is the agent-to-agent and session-to-session handover.

### OBSERVATIONS
- PC0's "Gaps tested" names verifying, deciding what to keep and handing over as holding no practice. But its own territory table also shows no practice for *committing to a design* or *treating the record*. The gap list leaves out two of the empty moments.
- None of the three charters' gap lists names a moment that is empty across all three layers. Every one of the six moments holds at least one procedure, rule or practice (deciding what to keep has rules RU1/RU3 but no procedure). So H7's "nothing at all" is true only of the sub-case of handing over to an agent or session, not of a whole named moment.
- M1 is a method but its main section is headed "## Rule". It is also internally inconsistent: it says four is "the empirical floor", then "sometimes 3 is enough" and "below 3 the failure mode is predictable".
- methods/README.md: the `---` directly after the line "A procedure that cuts or defers anything is held by them." has no blank line before it. In CommonMark that turns the paragraph into a setext H2 heading instead of a horizontal rule.
- RU0 itself declares no `trace`. The schema does not require it, because the requirement applies only to RU[1-9] ids, so this is consistent but worth noting.
