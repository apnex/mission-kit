### layer-charters.H5
A rule must declare `trace` in frontmatter: "the observable in the record that shows it was kept or broken, required by the catalogue contract" (rules/README.md, Member shape).
The schema enforces this: schemas/catalog-entry/v1alpha1/catalog-entry.schema.json requires `trace` when category is `rule` and the id matches `^RU[1-9][0-9]*$`, with minLength 20.
A practice "declares no `trace`; if it acquires one, it is a rule and moves" (practices/README.md, Member shape).
A rule may optionally name an enforcer in `enforced-by` (pattern `^tools/`) "when a tool checks it". `tools/check-enforcers.sh` checks that the named tool exists. "a rule with no tool yet is still a rule, and is checked by reading the trace."
The schema's description of `trace` agrees: "Naming a tool that checks it is enforced-by's job, and is optional."

### layer-charters.H6
The order comes from methods/README.md (M0), "Placement". Ask in this order and stop at the first yes:
1. Is it a limit a system is built toward, in force for every system with the traits it names? Then it is an axiom (axioms/).
2. Does following it produce a result of its own (a verdict, an artifact, a record)? Then it is a method (methods/). Guidance that only requires a record to carry something is a rule.
3. Does it govern how an artifact is written, its form, whatever the work was? Then it is style (style/).
4. Does it leave a trace in the record of the work that a check could test? Then it is a rule (rules/).
5. Otherwise it is a practice (practices/).
RU0, PC0 and S0 each cite this one statement unchanged: "axiom, procedure, style, rule, practice, asked in that order".
