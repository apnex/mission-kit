## P1 moved to style as S16 - director ruling, on review

**Ruling.**\
`P1` moves to style as its own rule, under a new identifier, and no legacy is carried: no stub.

**Applied.**
- `P1` became `S16`, *Path A / Path B - one complete path per substrate in a workflow document*; its body is unchanged. `S1`, `S4` and `S7` cite `S16`; `P3`'s edge to `P1` is dropped.
- Patterns keeps *variation in environment* as a named gap: the force is real for systems, and the only member was a document layout.
- The style charter places `S16` in the document-type row and composes it with `S7`; ten of sixteen rules are now held only by reading.

**What the ruling removed, and what replaced it.**\
The stubs left by earlier moves were what kept a retired id occupied, so dropping the stub would have silently dropped the guarantee that an id is never issued twice.\
`tools/check-id-reuse.mjs` now derives retired ids from git history and fails the gate if a current entry holds one; the root README's identity rule says so.\
It was mutation-tested on a deleted id, a renamed id and one moved out of the catalogue.\
Its first draft missed an id edited in place, found when the move landed in two commits and `P1` did not register as retired; that case is now held too.\
It found two reuses that predate it - `A0` and `C1` were each held by a different entry before - named in the tool as history, so frozen records citing them before those dates mean the earlier entry.

**Measured.**\
Run `p0-02`, after only: `p0` 16 / 16, `s0` 14 / 14.\
Suite edits to `p0` `Q4` and `Q6` are recorded in the evaluation README.

## Recorded, not changed

- **Four forces with no pattern.** Each is a claim no member fills. **Trigger for each: a second occurrence of a shape for it in contexts that share no author.**
- **`status: superseded` has no holder.** The schema still offers it and the sets check still refuses it. Removing the value is a schema change. **Trigger: the next change to the catalogue-entry schema.**
- **One gate run failed `sets behaves`** on the empty-members case, then passed in three gate runs and three standalone runs; the failing output is kept at `M5.5-08-sets-flake-capture.txt`. Cause not found; the run printed no generate-index error to separate it. **Trigger: a second failure of that case.**
- **The sets-test failure recurred** on 2026-10-05, on a different case (capture `sets-flake-capture-2.txt`), which fired the trigger. Cause found by reading the test: it piped generate-index's output into `grep -q` under `pipefail`, so whenever `grep` matched and exited before the writer finished, `SIGPIPE` failed the pipeline and a correct refusal read as absent. Fixed with a herestring, the same fix `check-entry-body.sh` already carries.
